# 外部 H3 优化方案竞品基准与极致差距分析（只读）

> 来源：子代理 `e6814c39-83f3-4cef-bbc3-bdab8b37839a` 交付（只读，未改代码）。本文件为落地归档，供审阅。

## 核心结论

- **外部确实有推到极限的具体方案**（NVIDIA RTX5090 保轨迹 231s/4.52×、Sol-H3 换配方 39.8s），但两者的极限都依赖本仓红线外的手段（50-step 跨步缓存、LTX 精修轨迹），**不可直接 copy**。

- **本仓 DiT 的 GEMM 本征已到硬件极限**：INT8 GEMM 98-99% 峰值（C5b 三层独立验证 sm_120 无更快 INT8 指令），sol-attn `cute_sm120` 真核已落地（480p hits=400/400，DiT −4.2s）。NVIDIA 在同卡 kernel-only 也只拿到 1.08×。**GEMM 本征无外部超额收益可抄；但 kernel 融合层（QKV merge / QKNorm+RoPE）仍有 −0.6~−1.2s 可抄**（见下 P1）——「到极限」仅指 GEMM 本征，不含融合层。

- **唯一真实、可抄、不违合同的工程差距 = VAE decode 段**（学 Comfy 0.36 kitchen 的 int8 融合 decode + pinned/async D2H 流水）：768p 可回收约 5-9s、480p 约 1-2s。这是优化方向。

- ~~跨步缓存 / VSA / VDN / LTX / NVFP4 / W8A8 / CPU offload 全部 REJECT~~ → **此句已勘误（见下「拒绝清单勘误」）**：把 7 项本质不同的技术压成一行 REJECT，混同了「本仓约束不适用」「N/A（不同模型）」「有界误差 opt-in 档」三种性质，且与事实有 4 处冲突。**没有一项是技术性死亡。**

## 一句话

不要再找更快的算法——turbo4 4-step 质量地板上所有更快的外部数都来自换轨迹；DiT 已极致，剩下的秒全在 VAE decode 工程化。

## 拒绝清单勘误（2026-10-05，子代理 faa4c84c 逐项重审）

原「全部 REJECT（撞红线或已证不买墙钟）」一句被用户指出**非常不合理**——重审确认：7 项里 **4 项拒绝理由写错或归类错误**，且 **7 项中没有一项是技术本身被证伪**。正确分桶如下。

**桶 C（技术性死亡，对保质量加速而言）：无。**

**桶 A（本仓约束下拒绝，技术在他处可能有效）：**

| 技术 | 原错误理由 | 修正后的真实理由 | 约束性质 |
| --- | --- | --- | --- |
| 跨步缓存（Tea/Mag/EasyCache） | 「纯原理否决」 | 8-step **实测**只跳 0–1 步（−12% DiT）且 MagCache 质量崩（MAE 52–68）；4-step 冗余被蒸馏榨干（外部 LightX2V #579 同证）。**是实验结论非原理禁令**；但 turbo4 4-step 上仍零实验 | 实验结论（可复核） |
| VSA（可训练稀疏注意力） | 「需要训练」 | 需训练预算（32×GB200 量级）+ 换学生权 → SKU 隔离，超本仓训练能力。**可训练稀疏构造上可近无损**（87.5% 稀疏 loss 不降），与推理时稀疏是两个质量类别，不应混谈 | 预算/合同约束 |
| VDN-the-model（OpenVDN 权重） | 「撞红线」 | ① 换学生权=换轨迹；② 加速叙事不含 VAE（对本仓 VAE 主墙无贡献）；③ sm_100/B200 核不可用于 sm_120。**合同外+硬件外，非技术死** | 合同+硬件约束 |

> **VDN 二次勘误（2026-10-05，子代理 e4780569）**：上行仅针对 **VDN-the-model**（训练好的权重）。用户指出 VDN 核心是「**线性**」——深拆确认我们此前**机理盲**：VDN 实为「局部滑窗 softmax + 双向线性记忆」**混合架构**（非纯线性），其线性分支用 delta 规则把 KV 历史压进固定 d×d 状态 → **O(N)+恒定内存**。**这命中我们 768P 的 O(N²) 内存墙，而稀疏 softmax（仍要物化 O(Nk)）在原理上给不出这个性质。** 线性注意力是改了注意力数学形式的**独立机制族**（非族2 稀疏变体）。**裁决：VDN-模型维持否决（合同外），但「线性/混合注意力机制」应从拒绝改为重开调研**——优先落点 SLA 式「稀疏+线性补偿」叠加在现有 sol 栈上（marginal 块走线性，成本<0.5%，稀疏度 70%→95%）。详见 `2026-10-05-vdn-linear-attention.md`。
| NVFP4 DiT 权重 | 「撞红线」 | **理由错误**（本仓 TE 已用 NVFP4）。真实：5090 实测**不买墙钟甚至倒贴**（社区 dequant→INT8 GEMM 路径，非原生 FP4 MMA）；原生 sm_120 FP4 GEMM 工程量大、预期收益 < INT8 已到手。**是 ROI 问题非红线问题**；质量上仅是有界误差精度档（同 TF32 族） | 工程 ROI |
| W8A8 | 「撞红线」 | **本仓已实质运行 W8A8 变体**（INT8 权 + 激活 per-row INT8 quant→INT8 GEMM）。外部 W8A8 标签相对本仓现状**无新增速度可买**。**不是死路，是已到站** | 已到站 |

**桶 N/A（归类修正）：**

| 技术 | 修正 |
| --- | --- |
| LTX（LTX-Video 精修轨迹） | **不同模型 + 不同 VAE**，对「加速 H3」是类别外参照物。应标 **N/A** 而非 REJECT——列入 reject 清单会造成「考虑过又否决了一个 H3 技术」的假印象 |

**桶 B（值得便宜复查，非判死）：**

| 技术 | 重看角度 | 便宜实验 |
| --- | --- | --- |
| 跨步缓存 @ turbo4 | 方法论弱点补课：turbo4 上纯原理拒绝、零实验 | **2–3 天 opt-in**：TeaCache 保守阈值（0.02，retain 首末步），量 skip 命中率+waffle+人眼。预期「跳 0–1 步、收益 <0.5s」从而**以实验而非教条封档**；小概率白捡 T1 档收益 |
| CPU offload（768P 限定） | 原「不买墙钟」**理由写错**：它正是 roadmap §8.5 登记的 768P 全 sol 32GB OOM 墙**解锁钥匙**。应重新定位为 **capability unlock（能力解锁）非 latency win** | **纸面账（半天）**：高分 QKVO(~5.5GiB)+部分 INT8 窗挪 host，PCIe ~25GB/s 往返税 vs 高分 sol 收益能否闭合为正。账闭合不了再正式判死——但理由要写对 |

**真正值得动手的只有 1 项半**：跨步缓存 @ turbo4（B，2–3 天，把教条升级为实测封档 + 小概率白捡）；CPU offload 768P 纸面账（B−，半天，关联 T4-e）。其余 5 项维持拒绝，但理由须按上表改写。

## sol-h3 官方一手重分析勘误（2026-10-05，子代理 5b096d05）

基于官方源码+论文+社区对照，对本文件此前 sol 相关结论的纠偏（详见 `2026-10-05-sol-h3-official-reanalysis.md`）：

1. **「sol-attn 已极致/真核已落地」需限定**：真核已接、480p hits=400/400 属实，**但只用了一半官方 MMDiT 接线**——官方配方=sink 保文本 K/V **+ 文本 query 行整个 dense + 前 2 层 dense + 前 10 步 dense**；我们接了 sink（K/V 侧）但 `FIRST_DENSE_*=0` 全稀疏、无文本 query 行 dense。**这是 sol_cute 臂能否往产品默认挪的关键 A/B，此前未识别。**
2. **「kernel 融合层仍有 −0.6~−1.2s 可抄」范围确认偏小**：官方 Pillar-1 完整含 **QKV-merge / fused QKNorm+RoPE / GEMM+GELU / torch.compile 或 CUDA Graph 捕获** 四项——前两项已在案，**CUDA Graph 捕获（Spark 1.39× 明确含 graph capture）此前完全缺失未列**。剩余可榨 DiT 侧约 5–15% 量级（非倍数级，官方 5090 阶梯 Pillar-1 全部仅 1.08×）。
3. **Sol-Attn 是近似算法非 bit-exact**：官方给 PSNR/SSIM/LPIPS 从不声称 bit-exact；社区「lossless」仅指 all-exact 模式（tau 极端化）。我们 480p 全 hit 的 checksum 变化来自官方算法本身的 proxy-score reuse，预期内。
4. **大方向获官方印证**：Sol-H3 官方 4-step 栈（8×B300，39.8s 类）**恰恰也不用跨步缓存而用蒸馏**——与我们 turbo4 路线同构，证实「turbo4 上 cache 冗余已榨干」非误判。
5. **TeaCache 桶 B 表述强化**：官方 5090 阶梯最大单项正是跨步缓存（708→231s，3.07×），但那是 50-step BF16 冗余；turbo4 4-step 与官方 4-step 栈一致地不用它——桶 B 的「2-3 天 A/B 以实验封档」维持，预期零跳步有 IonDen 先验 + 官方 4-step 栈旁证。
