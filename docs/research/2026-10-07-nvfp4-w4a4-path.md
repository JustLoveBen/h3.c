# NVFP4 W4A4 GEMM 路径调研（sm_120 / RTX 5090 / CUDA 13）

> **日期：** 2026-10-07  
> **调研性质：** 纯代码/文献调研，无 GPU、无 SSH。  
> **判定（TL;DR）：需实测（Conditional GO）** — 工具链齐备（PTX/CUTLASS/cuBLASLt 均已公开 sm_120 NVFP4 支持），但 (a) cuBLASLt FP4 在 sm_120 的实际命中率**未证实，需实测探测**；(b) W4A4 的端到端收益取决于动态激活量化开销，需按本仓真实 GEMM 形状实测；(c) 质量侧存在已发表先例（SVDQuant/Nunchaku），但本仓 33B 视频 DiT 无现成 NVFP4 权重，需自建量化管线。

## 1. sm_120 FP4 硬件能力

### 1.1 PTX 指令（已公开，可直接 inline asm）

sm_120a / sm_120f 提供 **warp 级 block-scaled MMA**，NVFP4 唯一形状固定为 **m16n8k64**：

```ptx
mma.sync.aligned.kind::mxf4nvf4.block_scale.scale_vec::4X.m16n8k64.row.col.f32.e2m1.e2m1.f32.ue4m3
  d, a, b, c, scale_a, {byte_id_a, thread_id_a}, scale_b, {byte_id_b, thread_id_b};
```

- 操作数 A/B 为 E2M1（FP4），累加器 F32；scale 类型 UE4M3（E4M3 无符号变体），`scale_vec::4X` 对应 K=64 内每 16 元素一个 scale（NVFP4 微块 16）。
- 架构限定：`sm_120a`（功能集）；`sm_120f`（family 兼容）自 PTX ISA 8.8（CUDA 12.9）起支持。本仓目标 CUDA 13，工具链满足。

**依据：**
- PTX ISA v9.2「Multiply-and-Accumulate Instruction: mma」「Block Scaling for mma.sync」（docs.nvidia.com/cuda/parallel-thread-execution，表 36 及 mma 语法节）。
- Colfax Research, *NVFP4 Blockscaled GEMM on NVIDIA RTX Pro Blackwell GPUs (SM12x)*（research.colfax-intl.com，2025）— 明确 NVFP4 唯一 PTX 形式与 16×8×64 固定形状。

### 1.2 CUTLASS 4.x 公开头（已公开，官方示例存在）

CUTLASS 4.x 原生支持 sm_120 block-scaled NVFP4 GEMM：

- **示例：** `examples/79_blackwell_geforce_gemm/79a_blackwell_geforce_nvfp4_bf16_gemm.cu`（NVFP4→BF16 输出）、`79b_blackwell_geforce_nvfp4_nvfp4_gemm.cu`（NVFP4→NVFP4 链式）、`79d`（grouped）、`80b`（稀疏）。文件头注释明确：「NVFP4 MMA has 2x throughput compared to MXFP8 MMA and 4x throughput compared to Ada Tensor Core FP8 MMA」；GeForce RTX 50 不支持 TMA multicast（cluster 必须 1×1×1）与 dynamic datatypes。
- **核心组件：** `cute/arch/mma_sm120.hpp`、`cute/atom/mma_traits_sm120.hpp`、`cutlass/gemm/collective/sm120_blockscaled_mma_tma.hpp`；CuTe DSL 提供 `MmaMXF4NVF4Op`（E2M1×E2M1→F32，UE4M3 scale）。
- **已知坑：** CUTLASS issue #2906 报告 79a 在 RTX 5090 / CUDA 13.1 / CUTLASS 4.3.4 上 TMA descriptor 未 64B 对齐导致 misaligned address 崩溃，需 `alignas(64)` Params/TMA + `alignas(128)` SF smem 的本地补丁；社区 fork 修复后在 5090 上测得 8192³ 约 3.74×（相对未注明基线的加速比，绝对 TFLOPS 数据不完整，**引用存疑**）。

**依据：**
- github.com/NVIDIA/cutlass `examples/79_*` 源码文件头（79a/79b）。
- CUTLASS 文档「Warp-Level MMA Instructions Programming Guide」（docs.nvidia.com/cutlass/4.6.2，MmaMXF4NVF4Op 构造与 sm_120a+ 要求）。
- github.com/NVIDIA/cutlass issue #2906（对齐 bug + 社区 benchmark）。
- lna-lab/blackwell-geforce-nvfp4-gemm `docs/sm120-architecture.md`（CUTLASS 4.0 sm_120 组件清单，7× RTX PRO 6000 实测）。

### 1.3 cuBLAS / cuBLASLt FP4 GEMM（API 存在，sm_120 命中率未证实）

cuBLASLt 已暴露 NVFP4 block-scaled GEMM 所需的全部 API：

- 数据类型：`CUDA_R_4F_E2M1`（A/B 操作数）。
- scale 模式：`CUBLASLT_MATMUL_DESC_A_SCALE_MODE` / `B_SCALE_MODE` = `CUBLASLT_MATMUL_MATRIX_SCALE_VEC16_UE4M3`（每 16 元素一个 E4M3 scale，即 NVFP4 微块语义）；C/D/D_OUT 用 `CUBLASLT_MATMUL_MATRIX_SCALE_SCALAR_32F` + device scale 指针；指针模式要求 `CUBLASLT_POINTER_MODE_DEVICE`。
- 最低版本：TensorRT-LLM 注释「Requires CUDA 12.8+ and cuBLASLt」。本仓 CUDA 13 满足。

**已证实的落地案例：** TensorRT-LLM PR #7943（commit 928247a）实现 `Fp4ScaledMM`（`cublasFp4ScaledMM`），配置了完全上述属性组合，并与 CUTLASS 参考实现对齐验证。搜索结果宣称该路径在 SM120 上工作，但 TRT-LLM 的 benchmark 未区分 sm_100/sm_120。

**关键不确定性（未证实，需实测探测）：** cuBLASLt 的启发式（`cublasLtMatmulAlgoGetHeuristic`）是否在 sm_120 上为 NVFP4 形状返回原生 block-scaled MMA 算法，还是静默 fallback 到「dequant→BF16 GEMM」模拟路径。若是后者，性能可能不优于 INT8。本仓 C5a 实测过 INT8 形状 `algos=1`（cublasLt 无备选），FP4 形状的启发式行为需要同样探测。

**依据：**
- TensorRT-LLM PR #7943 / commit 928247a（github.com/NVIDIA/TensorRT-LLM）— `CublasFp4ScaledMM.cpp` 完整属性配置代码。
- cudnn-frontend `samples/cpp/matmul/blackwell_nvfp4_mxfp8_block_scale_matmul.cpp`（NVFP4/MXFP8 block scale，128×4 SF 布局提示，要求 cuDNN ≥9.7）。

### 1.4 第三方性能参考点

- Infatoshi/nvfp4-sm120：通过 `torch._scaled_mm`（BlockWise1x16 + SWIZZLE_32_4_4，底层 cuBLASLt）在 sm_120 上测得 16384³ NVFP4 GEMM 持续 **~1100 TFLOPS ≈ 密集 FP4 峰值的 55%**，并归因「sm_120 cuBLAS 成熟度」。由此反推 sm_120 FP4 密集峰值约 **2000 TFLOPS**；本仓 C5b 实测 INT8 峰值 745.7 TOPS（docs/superpowers/plans/2026-10-05-h3-optimization-roadmap.md:217），比值 ~2.7×，与官方「NVFP4 = 2× MXFP8」口径相符。**（1100 TFLOPS 为第三方单点，未交叉验证。）**
- Colfax SM12x 教程提供 CuTe DSL 手写 NVFP4 GEMM 的完整路径，作为主循环低于 cuBLAS 时的备选。

## 2. 现有 nvfp4_cuda 实现盘点

**结论：当前 TE 的 NVFP4 是「软件 dequant → FP32 GEMM」，完全没有使用硬件 FP4 张量核；其存储/scale 布局解析层可复用，GEMM 层不可复用。**

### 2.1 实现结构（`h3_nvfp4_cuda.cu` / `h3_nvfp4.h`）

- **权重存储格式**（Comfy Qwen3VL NVFP4，`h3_nvfp4.h:14-21`）：
  - `weight`：U8 `[N, K/2]`，packed E2M1 nibble（hi_first：高 nibble→偶数 K）。
  - `weight_scale`：F8_E4M3 `[N, groups]`（盘上为 cuBLAS tiled/swizzled 布局，需 `h3_nvfp4_unswizzle_scales_u8` 还原为逻辑 `[N, groups]`）。
  - `weight_scale_2`：F32 标量（per-tensor 二级 scale）。
  - 可选 AWQ 平滑：`pre_quant_scale` BF16[K]（仅 o_proj / down_proj）。
- **CUDA 路径**（`h3_nvfp4_cuda.cu`）：
  1. mmap 的 safetensors 直接 H2D packed+scales（`nvfp4_te_packed_preload`，一次性 bulk 上传 50L×7 linear 到 GPU arena，`h3_nvfp4_cuda.cu:979-1205`）。
  2. `nvfp4_dequant_kernel`（`h3_nvfp4_cuda.cu:417-440`）：每线程一个 packed byte → 两个 FP32 输出，`kFp4E2M1` 查表 × `f8e4m3_to_f32(scale)` × `scale2`。
  3. 可选 `nvfp4_pre_quant_kernel`（AWQ 平滑，`h3_nvfp4_cuda.cu:443-448`）。
  4. **GEMM 为 FP32**：`h3_cuda_gemm_f32_dd`（`h3_gpu_cuda.cu:2436-2507`，底层 `cublasSgemm` / `cublasGemmEx CUDA_R_32F`）。
- 即 TE 的 NVFP4 只是**省显存/省 H2D 带宽**（15GB→~7GB packed），GEMM 本身跑在 FP32 CUDA 核上——对 TE（token 数少、GEMM 占比小）够用，对 DiT（GEMM 为绝对主墙）这条路没有意义。

### 2.2 可复用 vs 不可复用

| 组件 | 复用判定 | 说明 |
|---|---|---|
| safetensors NVFP4 解析（`h3_nvfp4_find_linear` / `h3_nvfp4_store_copy` / unswizzle） | **可复用** | DiT 若走 NVFP4，权重文件可用同一打包约定（U8[N,K/2] + E4M3 scale[N,K/16] + F32 scale2）。注意 DiT 侧需决定 scale 布局是否直接保持 swizzled（硬件 GEMM 要求 128×4 布局）以省 unswizzle。 |
| host/device packed 缓存与 mmap H2D 框架 | 部分可复用 | DiT 已有自己的 INT8 weight window/缓存体系（`h3_w4a8_cache.c`），NVFP4 权重应挂到该体系而非 TE 的 arena。 |
| `nvfp4_dequant_kernel` + FP32 GEMM | **不可复用** | 软件 dequant 路径的性能上限远低于 INT8 cublasLt（dequant 写 N×K FP32 + FP32 GEMM 双重带宽），仅可作正确性参考实现。 |
| FP4/FP8 转换表（`kFp4E2M1`、`f8e4m3_to_f32`） | 可复用 | 量化管线（host 侧权重打包、激活量化 kernel）可直接用。 |

### 2.3 现有 DiT INT8 路径（对照）

- DiT GEMM 走 `h3_cuda_gemm_i8_dequant_f32_w_act[_dev][_epi]` 族（`h3_dit_w4a8.c:1590/2780/2928/3038/3071/3140/3170`），底层 cublasLt INT8×INT8→INT32（`h3_gpu_cuda.cu:2590+`），ConvRot 旋转权重预量化，激活动态 per-row absmax 量化（`h3_gpu_cuda.cu:393-506` 的 quant/dequant/swiglu-requant 融合 kernel 族）。
- 形状：QKV `[3*INNER=21504, HIDDEN=5376]`、OUT `[5376, 7168]`、FC1 `[2*14336, 5376]`（SwiGLU 合并）、FC2 `[5376, 14336]`，50 块（`h3_dit_w4a8.h:55-74`）。M = 序列长度（480P ~数千 token 量级）。
- INT8 已达 sm_120 硬件峰值 98-99%（C5b，roadmap:16/217），cublasLt 无备选算法（C5a，roadmap:219）。

## 3. W4A4 vs 现状 INT8 的收益/精度权衡

### 3.1 算力与带宽收益（理论）

| 项 | INT8（现状） | NVFP4 W4A4 | 依据 |
|---|---|---|---|
| GEMM 峰值算力 | 745.7 TOPS（C5b 实测） | ~2× INT8（≈1490-2000 TFLOPS；CUTLASS 79a 文件头「2× MXFP8」；第三方实测 16384³ 达 ~1100 TFLOPS=55% 峰值） | cutlass 79a 注释；nvfp4-sm120 README；roadmap:217 |
| 权重显存 | 8 bit/param（33B≈33GB，本仓按 window 分块常驻） | 4 bit/param + E4M3 scale（K/16）≈ **0.5625× INT8**（每 16 元素：INT8 16B → FP4 8B+1B scale） | NVFP4 格式定义 |
| 激活/中间带宽 | 每 GEMM 输入输出走 FP32/FP16 缓冲 | GEMM 输入 FP4 packed（1/8 FP32），但激活需**在线量化**（每次 GEMM 前 per-16 块 amax→E4M3 scale→E2M1 打包），输出通常为 BF16/FP32 累加 | PTX mma 语义 |

**GEMM 纯算力期望：** 若 cublasLt FP4 能达到 INT8 同等的峰效率（98%），则 GEMM 时间 ~0.5×。DiT GEMM 占 hot 主墙大头（10.37s DiT / 63%，roadmap:16），理想上限 ~**−30% DiT 时间**。

**必须扣除的开销：**
1. **激活在线量化**：INT8 路径已有 per-row absmax 量化 kernel（每元素 1 次读+1 次写）。NVFP4 需要 per-16 块 amax + E4M3 scale 计算 + nibble 打包，每元素约同等访存但写量减半（packed byte）；且 scale 需按硬件要求的 swizzled（128×4）布局写出，kernel 复杂度更高。粗估每 GEMM 额外 ~1 次激活全量读写（M×K），对 K=5376-14336 的形状，量化开销约占 GEMM 时间 5-15%（未实测，需按真实形状测）。
2. **K 维对齐**：NVFP4 微块 16 → K 必须 16 对齐。本仓 K = 5376 / 7168 / 14336 均为 16 的倍数（5376=16×336 ✓，7168=16×448 ✓，14336=16×896 ✓），N = 5376/21504/28672 亦全部 16 对齐 ✓。**形状天然兼容，无需 padding。**
3. **累加精度**：FP4 MMA 累加为 F32，与 INT8 的 INT32 累加精度语义不同；对 4-step turbo 采样链的漂移需实测（waffle 金线口径）。

### 3.2 精度风险（DiT 激活量化敏感）

- **通用结论：** DiT/扩散模型对激活量化的敏感度高于 LLM，主要源于激活离群通道（outlier channels）。SVDQuant（ICLR 2025）是首个成功的 DiT W4A4 PTQ：低秩（rank 32/64）BF16 分支吸收离群 + 4-bit 主分支，FLUX.1 12B 上 NVFP4 保画质、显存 −3.5×、RTX 5090 实测 3.1× 于 W4A16（INT4 weight-only 引擎对照）。
- **视频 DiT 先例：** Wan2.2-I2V 的 Timestep-Aware SVDQuant-GPTQ（W4A4）报 VBench 仅 −0.9%（需 timestep 分桶 + per-layer 激活 clipping 标定 + GPTQ）；DeltaQuant（CVPR 2026）报 W4A4 SVDQuant 在 I2V 首帧出现可见失真，需时空平滑标定修补。**即裸 W4A4（无低秩分支、无标定）几乎必然出现可见退化。**
- **本仓特殊背景：** 现状 INT8 ConvRot 已是「旋转抑制离群 + per-row 动态量化」的强基线，质量金线苛刻（latent checksum / waffle 0.75-0.95）。NVFP4 W4A4 相比 INT8 的精度损失是非零的，必须有 (a) 旋转/平滑（ConvRot 可直接沿用——旋转同时利于 FP4 激活量化）+ (b) 可能需要的低秩补偿分支。低秩分支会增加一条 BF16 GEMM（rank 32-64），吃掉部分 FP4 收益。
- **W4A8 折中（FP4 权重 + FP8 激活）：** sm_120 的 block-scaled MMA 支持 mxf8f6f4（E4M3×E4M3 等混合 FP8/FP6/FP4，scale_vec::1X，K=32）与 mxf4nvf4（必须双侧 FP4）。**「W4A8」在硬件上没有「一侧 FP4 一侧 FP8 且各自带 block scale」的原子指令**；可行形态是 MX 混合（mxf8f6f4 允许 A=e4m3, B=e2m1，scale 为 UE8M0/1X）——即 **MXFP4 权重 × MXFP8 激活**（UE8M0 scale，非 NVFP4 的 UE4M3）。精度上 MXFP8 激活远好于 FP4 激活（动态范围 8-bit 指数），权重侧 MXFP4 比 NVFP4 略差（UE8M0 scale 粒度粗）。这是**无需低秩分支也可能保质的折中**，但算力只有 MXFP8 档（≈INT8 的 1× 而非 2×？——按 CUTLASS 79a 注释「NVFP4=2×MXFP8」，MXFP8 与 INT8 档位相当，则 W(MXFP4)A(MXFP8) 混合的实际吞吐取决于指令档，**未证实，需实测探测**）。另一形态是 FP4 权重 dequant 到 FP8 再跑 FP8 GEMM（等效 W4A8），但 dequant 开销会吃掉收益。
- **精度结论：** 质量门能否过，取决于是否引入 SVDQuant 式低秩分支与标定管线。**无补偿的裸 W4A4 预期不过金线；带 ConvRot（已有）+ 可选低秩分支 + timestep 标定的 W4A4 有已发表先例支撑。**

### 3.3 收益小结（对 33B 视频 DiT）

- **速度：** GEMM 理论 2×，扣激活量化与可能的低秩分支后，DiT 净收益现实区间 **1.3×–1.8×**（需实测，对应 hot DiT 10.37s → 5.8–8.0s）。
- **显存：** 权重 0.5625×，对 768P 的 32GB OOM 墙（INT8 窗+激活 28.8GiB，roadmap:218）有直接缓解，可能重开 768P 全 sol 路径——这是 INT8 无论如何拿不到的**结构性收益**。
- **代价：** 需要全新的 DiT NVFP4 量化权重（无现成 safetensors，需自建量化管线：ConvRot 旋转 + per-16 块 E4M3 scale + 可选 SVD 低秩 + timestep 标定集），工程量大于 GEMM 本身。

## 4. 施工方案

### 4.1 分阶段方案

**Phase 0 — 可行性探测（1-2 天，无质量风险，决定 GO/NO-GO）：**

1. 新建 `bench/cutlass_evt/bench_cublaslt_fp4.c`（复用 E1 的 `bench_cublaslt_i8.c` 骨架）：
   - 按 TRT-LLM `cublasFp4ScaledMM` 的属性组合配置 cublasLt FP4 GEMM（`CUDA_R_4F_E2M1` A/B、`VEC16_UE4M3` A/B scale、BF16 输出、device pointer mode）。
   - 跑本仓 8 个真实 DiT 形状（QKV/OUT/FC1/FC2 × 典型 M），与 cublasLt INT8 同形状对比。
   - **判据（与 E1 同构）：**
     - `cublasLtMatmulAlgoGetHeuristic` 返回 0 算法或仅 fallback（性能 < 0.8× INT8）→ **NO-GO（cuBLASLt FP4 死）**，转 CUTLASS 79a 路径再测一轮；
     - ≥ 1.5× INT8 → GO 到 Phase 1；
     - 0.8×–1.5× → 算入激活量化开销后净收益不足 → NO-GO 或转 MXFP4/MXFP8 混合再测。
   - 需先在 sm_120 上确认 `CUBLASLT_MATMUL_MATRIX_SCALE_VEC16_UE4M3` 被接受（`cublasLtMatmulDescSetAttribute` 返回码）——**此点未证实，需实测探测**。
2. 同步用 CUTLASS 79a（带 issue #2906 对齐补丁）在同形状建对照，确定 cuBLASLt 不行时的自建核上限。

**Phase 1 — GEMM 后端接入（若 Phase 0 GO）：**

1. 权重侧：离线量化管线（Python/C 均可）把 DiT 线性强权重 → NVFP4 packed（沿用 TE 的 U8[N,K/2] + E4M3[N,K/16] + F32 scale2 约定，`h3_nvfp4.h:14-21`；但 scale 直接写硬件要求的 swizzled 128×4 布局，省运行时 unswizzle）。**保留 ConvRot 旋转**（旋转在 INT8 路径已验证抑离群，对 FP4 同样关键）。
2. 激活侧：在 `h3_gpu_cuda.cu` 新增 `h3_cuda_quantize_act_nvfp4_kernel`（per-16 块 amax → E4M3 scale + E2M1 打包，swizzled scale 写出），替换现有 per-row INT8 量化 kernel（`h3_gpu_cuda.cu:393-506` 族）的对应位置。
3. GEMM 调用点：`h3_dit_w4a8.c` 的 4 个调用点（`h3_cuda_gemm_i8_dequant_f32_w_act_dev*` at 2780/2928/3038-3071/3140-3170）按 env（如 `H3_DIT_NVFP4=1`）切换到新 `h3_cuda_gemm_fp4_bs_dev`（cublasLt FP4 或 CUTLASS 自建核）。INT8 路径整体保留，双轨共存（与现有 `h3_nvfp4_cuda_enable` 的 env 开关模式一致，`h3_nvfp4_cuda.cu:739-756`）。
4. Dequant/epilogue：FP4 GEMM 输出 BF16/FP32，现有 gate/SwiGLU/AdaLN epilogue 融合（`h3_dit_fused_epi.h`）从 INT32 acc 输入改为 BF16 输入，工作量集中在 acc 后处理 kernel 的 dtype 泛化。

**Phase 2 — 质量收敛（决定能否翻默认）：**

1. 金线复测：latent checksum 对比 + waffle 区间（480P 0.75-0.95 / 768P 0.75-1.05，roadmap:237）。
2. 若裸 W4A4 退化：叠加 (a) per-timestep 激活 clipping 标定；(b) SVDQuant 低秩分支（rank 32 BF16 GEMM，可与主 GEMM 并行/融合，Nunchaku 已证可行）。
3. 显存收益兑现：768P 重测 INT8 窗 OOM 场景（28.8GiB 账本 ×0.5625 权重侧 + 激活缓冲 FP4 化）。

### 4.2 后端选型决策树

```
cublasLt FP4 启发式命中原生 sm_120 核？
├─ 是（≥1.5× INT8）→ 用 cublasLt（零维护，与 INT8 路径同构）✅ 首选
└─ 否 → CUTLASS 79a 自建核（带 #2906 对齐补丁，嵌入 h3_dit_nvfp4.cu）
        ├─ ≥1.5× INT8 → GO（维护成本：CUTLASS 头文件依赖 + sm_120a 编译开关）
        └─ <1.5× → NO-GO：FP4 在本仓形状下无净收益，封档
```

**不建议**手写 PTX mma.sync 裸核：m16n8k64 atom 之上需要完整的 TMA 流水/swizzle/调度才有竞争力，E1 已证明手写公开头路径打不赢 cublasLt 私有核（bench/cutlass_evt/RESULT.md，0.53-0.58×）；CUTLASS 79a 已是公开最优。

### 4.3 scale 布局与 per-tensor vs per-block

- **必须 per-block（16 元素）**：NVFP4 硬件语义就是 16 元素微块 × UE4M3 scale；per-tensor 仅靠 F32 scale2 做全局二级缩放（与 TE 权重约定一致）。
- **布局**：硬件/cublasLt 要求 SF 按 128×4 tile swizzle（cudnn-frontend 示例与 CUTLASS `Sm1xxBlkScaledConfig::tile_atom_to_shape_SFA` 均为此布局）。权重 scale 离线 swizzle；激活 scale 在量化 kernel 内直接写 swizzled 布局。
- **与 INT8 ConvRot 共存**：env `H3_DIT_NVFP4=1` 切换；权重缓存（`h3_w4a8_cache.c`）增加 FP4 packed 槽位，与 INT8 窗互斥（显存不允许双份常驻），切换需清缓存重载。

### 4.4 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| cublasLt FP4 在 sm_120 不命中原生核（fallback dequant） | **高（未证实）** | Phase 0 探测，CUTLASS 79a 兜底 |
| 激活在线量化吃掉 GEMM 收益（M 较小、K 大时量化占比升高） | 中 | 量化 kernel 与上游 epilogue 融合（复用 E2 dequant+requant 对撞思路） |
| 裸 W4A4 质量退化（视频 DiT 首帧/细节敏感） | 中高 | ConvRot 已有；SVDQuant 低秩分支 + timestep 标定兜底；金线门禁 |
| 无现成 DiT NVFP4 权重，量化管线自建 | 中（确定性工作） | 复用 TE 打包约定；GPTQ 可选 |
| CUTLASS sm_120 对齐 bug（#2906） | 低 | 已知补丁 |
| 4-step turbo 链对 FP4 累加漂移敏感 | 中 | waffle 金线 + latent checksum 实测 |

## 5. 三态判定

**需实测（Conditional GO）。**

- **不是直接 GO**：cuBLASLt FP4 在 sm_120 的原生核命中率未证实（公开案例均未区分 sm_100/sm_120），且这是整个路径的盈亏分界线；W4A4 对 33B 视频 DiT 的质量影响无本仓数据。
- **不是 NO-GO**：与 E1（CUTLASS INT8 EVT）本质不同——E1 死于「公开头只有 m16n8k16 半速 atom」，而 NVFP4 的 m16n8k64 block-scaled atom 在 PTX/CUTLASS/cuBLASLt 三层均已公开且官方明示 2× 于 MXFP8；硬件能力无争议，质量侧有 SVDQuant/Nunchaku 在 RTX 5090 上的发表先例。
- **GO 的充要条件（Phase 0 探测，1-2 天可完成）：** cublasLt FP4 或 CUTLASS 79a 在本仓 4 个真实 GEMM 形状上 ≥1.5× cublasLt INT8（为激活量化开销留 0.5× 余量）。达到则进入 Phase 1；达不到则按 E1 格式封档证伪。

```
# FP4 W4A4（同上，--arm dit_nvfp4_w4a4；H3_DIT_NVFP4=1 由脚本注入）
```

**关键修正（方法论）：** P1 报的 rel_l2=1.74 是「1 步调度(σ:1→0)」与「8 步调度」的**跨调度**对比，非量化误差。8 步 σ 调度为 `1 0.9882 0.973 0.9524 0.9231 0.878 0.8 0.6316 0`，step1 仅走到 σ=0.9882。真正同调度逐步对比如下。

**逐步 latent 轨迹（mean / std / checksum 见 generate.log）：**

| step | INT8 mean | FP4 mean | INT8 std | FP4 std |
|---|---|---|---|---|
| 1 | 0.00114 | 0.00067 | 0.9818 | 0.9970 |
| 4 | 0.00847 | 0.00611 | 0.8948 | 0.9849 |
| 8 | 0.06660 | 0.09546 | 1.4229 | 1.2407 |

**raw latent 逐元素对比（FP4 vs INT8）：**

| 对比点 | rel_l2 | max_abs | 说明 |
|---|---|---|---|
| step1（同 8 步调度） | **0.0206** | 0.1223 | 单步 FP4 量化误差 ~2% — 健康 |
| step8（终 latent） | **1.3294** | 11.81 | 8 步后发散到 O(1) |

**判定：发散（divergent）。** 单步误差仅 2%（FP4 本身精度足够），但 8 步后 gap 从 0.02 涨到 1.33 —— 误差随步数**复利放大**，非有界、非自纠。flow-matching 采样对每步速度场误差敏感，W4A4 的速度误差沿轨迹累积 → 终 latent 与 INT8 不可比（rel_l2>1 意味着差异量级≈信号本身）。**全 W4A4 DiT 直接替换 INT8 不可行**；若要用 FP4 需 (a) 混合精度（敏感层保 INT8/FP8）、(b) 量化感知微调/蒸馏（SVDQuant-GPTQ 类），或 (c) 仅 W4A16（FP4 权重 + 高精度激活）。

**性能 sanity（同 8 步，5090）：**

| 臂 | DiT 总时 | 平均每步 | vs INT8 |
|---|---|---|---|
| INT8 gold | 106559.9 ms | ~13285 ms | 1.00× |
| FP4 W4A4 | 93861.7 ms | ~11695 ms | **0.88×（快 12%）** |

FP4 全程无 INT8 fallback（200 GEMM 全走 FP4 track），无 NaN/非法访存，latent 全程有限。W4A4 比 INT8 快 12%（未达理论 2×，受动态激活量化开销与 cudnn SDPA 主导）。

## P2.2 端到端视觉验证（2026-10-07，RTX 5090 / 192.168.0.238）— 对 P2.1 结论的关键修正

**动机：** P2.1 的 latent 指标（step8 rel_l2=1.33、cosine≈0）无法区分「FP4 产出**不同但有效**的采样」（混沌放大，可接受）与「FP4 产出**退化**采样」（真质量损失）。对混沌采样系统，同模型两个不同种子的终 latent 也 cosine≈0。唯一判据是解码后的视频。本节把本地 5.2GB VAE（`minimax_h3_video_vae_fp16.safetensors`，SHA-256 校验一致）同步到 238，跑完整 DiT+VAE 端到端出视频。

- frame 0：gold 近景双人、蓝紫地板 / FP4 隧道中央主体——**构图已不同**

- latent 数值指标（rel_l2/cosine/SSIM/PSNR）对混沌采样**不能**判定质量——它们对「不同但有效」的采样必然接近不相关。

## P3.4 饱和度信号与多 seed 确证实验（2026-10-07）— 待统计定论

**触发现象：** p01_sprint 上 FP4 视频逐帧饱和度（ffmpeg `signalstats SATAVG`）钉在 15-16（几乎恒定），INT8 gold 为 34-53（波动）。三个 FP4 prompt（p01/p05/p07）SATAVG mean 均低（18.5/23.0/14.3），gold p01 为 46.4。差异 2-3×。

**方法学局限（关键）：** 该差异**无法**在单样本下归因——FP4 与 gold 是混沌发散的不同样本，连色调都不同（FP4 HUEAVG 168° 青蓝 vs gold 148° 蓝紫），饱和度差异可能纯属"发散到了自然偏淡的样本"。latent 逐通道 std 分析显示 FP4 各通道为 gold 的 0.75-0.92×（均匀，无通道被压塌），**不足以解释 3× 像素饱和度差**。故单样本数据既不能证实也不能排除"FP4 系统性降饱和"。

**确证实验设计（多 seed 分布统计）：** 同 prompt（p01_sprint）× 6 个不同 seed（0x76800011-16）× 双臂（INT8/FP4）= 12 个端到端，测每个视频全帧 SATAVG 与 YAVG（亮度对照）。
- **判据：** FP4 饱和度分布系统性低于 INT8 且不重叠 → 确证系统性降饱和；分布重叠 → p01 低饱和为发散偶然；YAVG 两组应重叠（确认效应为色度特异）。

**早期数据（前 4/12，倾向无系统降饱和）：**

| arm | seed_11 SAT | seed_12 SAT | YAVG |
|---|---|---|---|
| INT8 | 18.8 | **13.8** | 95.4-95.5 |
| FP4 | **23.1** | 18.5 | 91.7-94.4 |
