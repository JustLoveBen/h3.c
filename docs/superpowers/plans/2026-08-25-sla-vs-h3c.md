## 0. 先钉死的尺子

质量金标（有声 T2VA cafe q1）：**75.4s**，DiT **47.5s**（host-stage 后 ~43s），checksum `0x3b3464adf6c39df2`，`--seconds 5`、cfg=1、**8 step**、INT8 ConvRot、272 tile。40–50s 在这条 dense 配方上到不了。

注意力金线：cuDNN fused SDPA，cafe packed **`T=15973, H=56, D=128`**。孤立 CUDA Sol：**cuDNN 46.7ms vs Sol 351ms（~7.5× 更慢）**。社区 Sol/SLA 赢的是 Sage / PyTorch SDPA / FA2，不是这把 fused cuDNN。

本仓 Sage：`H3_CUDA_SDPA_BACKEND=sage2` 默认关；满 seq 参考核 **~9s/层 vs cuDNN ~150–177ms**。真 Sage2++ MMA 未链入。

本仓 **没有** LoRA 加载器（C/CUDA 源码零命中 `lora`）。

## 1. SLA 是什么

论文：[arXiv:2509.24006](https://arxiv.org/abs/2509.24006)（*SLA: Beyond Sparsity in Diffusion Transformers via Fine-Tunable Sparse-Linear Attention*）  
代码：[thu-ml/SLA](https://github.com/thu-ml/SLA)

**稀疏 + 线性混合，要微调，不是 training-free。** 这点和 Sol-Attn 相反。

注意力权分成三档（块级，论文 `b_q=b_kv=64`）：

| 档 | 判定 | 计算 |
| --- | --- | --- |
| critical | pooled softmax 的 **top \(k_h\%\)**（论文默认 5%） | FlashAttention，\(\mathcal{O}(N^2)\) |
| negligible | **bottom \(k_l\%\)**（论文默认 10%） | 跳过 |
| marginal | 中间带 | 线性注意力 \(\phi(Q),\phi(K)\)，\(\mathcal{O}(N)\)，再加可学习 **Proj** |

代码旋钮：`topk = 1 - sparsity`。`topk=0.15` ≈ 85% sparsity（HF H3 Turbo）；论文主结果 `topk=0.05` ≈ 95%。SageSLA 注释写明 `topk = 1 - sparsity`。

线性支路 **不是** 对 marginal softmax 的无偏近似。论文 §4.2 原文：它是 learnable compensation，**必须微调目标模型** 才能对上分布。最终 \(O = O^s + \mathrm{Proj}(O^l)\)。

论文数字（**Wan2.1-1.3B**，seq≈30K，**不是 H3**）：

- 微调 2000 step、bs=64；相对预训练 &lt;0.1%
- 95% sparsity，注意力 FLOP −20×；5090 上 kernel vs **FlashAttn2** 13.7×；e2e 2.2×（注意力 97s→11s）
- training-free Sparge-F **85% sparsity：画质崩**（VA 0.002 vs Full 76.78；IQ 26 vs 62.5）
- Sparse-only 85% 微调后仍明显差于 SLA 95%

**SageSLA**：同一套 SLA 前向的 SageAttention/SpargeAttn 量化核（`SageSLA/`）。快路径绑 Sage，不是 cuDNN。SageSLA 只支持 `BLKQ=128, BLKK=64`（Hopper 反过来 64/128）。社区 issue：Hopper 上 Triton SLA 有时 **慢于 FA2**。

SLA2（arXiv:2602.12675，learnable routing + QAT）是后续论文，H3 Turbo 卡引用的是 SLA-1。

## 2. HF 上的 MiniMax-H3 Turbo-SLA 是什么

卡：[lightx2v/Minimax-h3-Turbo-SLA](https://huggingface.co/lightx2v/Minimax-h3-Turbo-SLA)（约 4 天前）  
真源 JSON：[minimax_h3_fp8_4step_5090_with_fp8_vae_sla.json](https://github.com/ModelTC/LightX2V/blob/main/configs/minimax_h3/dmd/minimax_h3_fp8_4step_5090_with_fp8_vae_sla.json)

**另一套权重 + 调度，不是给现有 8-step INT8 插 kernel。**

| 项 | Turbo-SLA | 本仓金线 |
| --- | --- | --- |
| 任务 | **4-step distilled FL2V** LoRA（`pipeline_tag: image-to-video`） | 有声 **T2VA** 8-step |
| 分辨率 | **768p**（JSON 1344×768，362 帧） | 864×480，5s/120 |
| 权 | BF16 LoRA 1.38GB（LightX2V）/ 1.96GB（Comfy）；α=128，打在 **FP8 DiT** 上 | INT8 ConvRot 整网 |
| 步 | `infer_steps: 5` + 4-step LoRA；`h3_step_update=training_euler` | 官方 8-step CFG 蒸馏轨迹 |
| 注意力 | `attn_type=dynamic_sparse_attn`，`sparsity_ratio=0.85`，`operator=sage2` | cuDNN fused dense |
| 对照片 | HF demo：**30-step base vs 4-step turbo** 并排 | **8-step INT8** cafe |
| 加速声明 | RTX **5090** LightX2V「约 2.5×」 | 4090；基线已是 cuDNN 不是 Sage |
| JSON 其它 | FP8 DiT/VAE、`use_compile`、`seq_p_size: 8` Ulysses、cpu_offload | 单卡、无 compile、无 Ulysses |

LightX2V 源码里正式 SLA 核注册名是 **`sla_attn`**，operator 枚举是 `triton` / `sage` / `magi`（见 `lightx2v/common/ops/attn/sla_attn.py`）。HF H3 卡写的是 **`dynamic_sparse_attn` + `operator=sage2`**，和 LightWan extreme 的 Wan 稀疏配方同一把旋钮。推理快路径实质是 **topk 块稀疏 + Sage2/Sparge 核**；sage 实现里看到的是 INT8 QK / FP8 V 的 block-sparse MMA，**不是**论文 Algorithm 1 那种 fused \(O^s+O^l\) 在本仓可链的 C 核。质量靠 **蒸馏 LoRA 已经在稀疏配方上训过**。

Comfy 权是「converted LoRA」，给 Comfy MiniMax-H3 工作流，不是 h3.c 的 safetensors 契约。

## 3. 对本仓的适配面

### 3.1 不换权重、只换 kernel — 会崩

论文要求微调。plug-and-play 的对照就是 Sparge-F：85% 稀疏、不训，视频质量接近不可用。H3 packed `[text|audio|video]` 比 Wan 更敏感（Sol 专章已写：无 sink 音频先坏；480p 小脸占极少 token）。

没有可跑的 **native SLA kernel**。Triton/SageSLA 是 Python 侧车，架构禁止。手写 CUDA 嵌套循环已经在 Sol 上输给 cuDNN 7.5×；SLA 还多一条线性支路 + 路由 LUT，没有证据会赢 fused cuDNN。

**不要假装 cafe 形状 bench。** 没有 native 核就没有 15973×56×128 对拍。

### 3.2 换 4-step LoRA + SLA — 对不上产品

- 本仓 **不能加载** LightX2V/Comfy LoRA。没有 merge、没有 α、没有对 INT8 ConvRot 的 delta 应用。
- BF16 LoRA 打在 FP8/BF16 基座上；本仓质量默认是 **INT8 ConvRot 整权**。把 LoRA 接到 INT8 上要么反量化（丢 INT8 金线、显存/速度故事变了），要么需要官方一起蒸馏的 INT8/SLA 权（没有）。
- **FL2V ≠ T2VA / F2VA / FL2VA。** 卡是 I2V/FL2V 768p；金线是无条件 T2VA cafe。即使 CUDA 已有 `--first-frame`/`--last-frame`，Turbo LoRA 也没承诺保住 480p 末帧锁（FL2VA f119 MAE~5.3 那条质量门）。
- `training_euler` + flow shift 6/3 是另一条采样；把 8-step INT8 轨迹改 4 步而无匹配蒸馏权，LightWan 文档已定为崩主题。

### 3.3 Sage2 operator — 本仓吃不到那 2.5×

HF/LightX2V 把稀疏算子绑死 **sage2**。本仓默认关 Sage；现有 sage2 核比 cuDNN 慢数量级。2.5× 是相对 **LightX2V+Sage2（再加 4 步蒸馏、FP8、5090，JSON 里还有 8-way seq parallel）**，不是相对 4090 上 8× dense cuDNN。

cuDNN 路径即使实现了「动态稀疏 mask」，也接不上 SageSLA 的 INT8/FP8 MMA 故事。

## 4. 质量

- **4-step vs 本仓 8-step：** 没有同配方对照。HF 只跟 30-step base 并排。本仓 8-step 已是 CFG 蒸馏；再砍到 4 步而不换匹配权 = 未蒸馏 4 步，红线禁止。
- **85% 稀疏：** 论文在 *微调后的 Wan 1.3B* 上 95% 可保 VBench；同一论文里 **不训的 85% 会炸**。H3 480p 人脸 / FL2VA 末帧锁是高频残差，块 topk 按 pooled 分数选 exact，背景大块更容易赢。Sol 社区已有「人脸终稿停用」；SLA 的线性补偿要靠训练，不是推理期 pooled-V 校正。
- 有声：H3 一条自注意力。稀疏若不保护 text/audio 前缀，对白/口型是第一张牌。Turbo 卡没写 H3 sink 策略。

## 5. 速度（诚实外推）

HF 2.5× **不能**当本仓乘数。拆他们的梯子：

1. **4 vs 30 步**（demo 对照）或至少 **4 vs 8**：步数才是大头。
2. Sage2 vs 他们原来的 SDPA/FA（本仓已经用 cuDNN 赢了 Sage）。
3. 85% 稀疏 vs dense Sage（核级；e2e 还要扣 MLP/AdaLN）。
4. 5090 + FP8 + compile；JSON 甚至写了 `seq_p_size: 8`。

本仓瓶颈：8× dense cuDNN，稳态 ~5.3s/step，DiT 47.5s（step1 unpack+plan ~10s 几乎不动）。

若 **幻想** 4-step 仍走现有 INT8+cuDNN、稀疏核 magically ≤ cuDNN：

- 只减步：DiT ≈ step1 10s + 3×5.3s ≈ **26s**（约 1.8× DiT），墙钟 75s → ~**54s**。TE+VAE 仍 ~21s。仍到不了 40s。
- 再乘「稀疏让注意力接近免费」：稳态里注意力不是 100%。Sol-Engine 在已融合的 480p H3 上 Sol 只再砍 ~12% 墙钟。乐观再砍数秒，不是 2.5×。
- 扣 LoRA/BF16 vs INT8：INT8 GEMM 优势可能吐回去，**4 步 BF16 不一定快过 8 步 INT8**。
- 扣「本仓没有 Sage2 MMA / 没有 SLA 核」：稀疏支路可能像 Sol 一样 **更慢**。

**没有 native SLA 核，本段全部是算术，不是实测。**

## 6. 和已证伪 Sol 的对比

| | Sol-Attn | SLA / Turbo-SLA |
| --- | --- | --- |
| 训练 | training-free | **必须微调**（或换蒸馏 LoRA） |
| 未选中块 | pooled-KV 近似校正 | 跳过或线性+Proj |
| 社区 H3 | kijai Triton 有 packed/sink | H3 适配是 LightX2V **另一套 4-step FL2V LoRA** |
| 本仓核 | 已写 CUDA；cafe **351 vs 47ms** | **没有** native 核 |
| 对标基线 | Sage / FA3 | Sage2 / FA2；H3 卡再叠 4-step |
| 质量默认 | 已停 | **不要做**（C） |

SLA 不是「Sol 换个名字更快」。它把质量押在训练/蒸馏上；速度押在 Sage 系核上。两笔本仓都付不起。

## 7. 若以后要做的最小实验（现在不要开）

现在 **不要写核、不要接 generate、不要拉 LoRA 进质量路径。**

若产品改口、愿意换配方，最小闭环按这个顺序，全失败即停：

1. **孤立核（必须 cafe 形状）** `T=15973,H=56,D=128`，device-resident，对拍本仓 cuDNN ~47ms。没有可链入的 C/CUDA SLA/SageSLA 就停，禁止 Triton 侧车冒充。
2. 核若不能稳定 &lt; 0.92× cuDNN：**停**（Sol 的 STOP 条件）。
3. 只有核赢了，才允许 opt-in 研究档：单独加载 **BF16 基座 + Turbo LoRA**（新加载器）、`--steps 4`、`training_euler`、FL2V 条件，**与 cafe T2VA 金线分目录**。门：主题/人脸/末帧 MAE/音频波形。过不了就关。
4. 禁止把该档的墙钟和 q1 75.4s 比成「同片加速」。

## 8. 分档

**C。** 原因汇总：训练依赖；Sage2 本仓更慢；BF16 LoRA 对不上 INT8 ConvRot；FL2V 4-step 不是 T2VA 8-step；cafe 形状未、也不能假装 bench；2.5× 不能平移。

不是 A（无证据保质量）。也先不标 B：B 需要先有赢 cuDNN 的核 + LoRA 加载 + 独立质量门，现阶段都不存在。
