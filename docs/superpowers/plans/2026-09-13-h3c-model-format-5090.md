# 5090 模型格式：INT8 ConvRot / W4A8 / NVFP4

Date: 2026-09-13  
不是实现计划。不改默认路径。不 commit。不编造秒数。  
对照：[accel-principle-matrix](./2026-09-11-h3c-accel-principle-matrix.md) · [turbo-implementation](./2026-09-11-h3c-5090-turbo-implementation.md) · [turbo-explainer](./2026-09-13-h3c-turbo-explainer.md)

**Goal:** 回答四件事——`pruned_int8_convrot` 是不是最合适的默认；W4A8 是什么；5090 上该用什么格式；NVFP4 社区权重怎么当加速档试、最终怎么多量化并存。

---

## 0. 结论先行

| 问题 | 答案 |
| --- | --- |
| `pruned_int8_convrot` 最合适吗？ | **作为金线默认：是。** 质量尺子过门、本仓 CUDA 路径成熟、5090 32GB 装得下。它不是「算力上限最优」，是「效果+工程」最优。 |
| W4A8 是什么？ | 权重 4-bit、激活 8-bit。文件名 `h3_dit_w4a8.c` 是历史命名；**今日产品金线走的是同文件里的 `open_int8`（INT8 ConvRot）**，不是 Kijai W4A8 权。Kijai W4A8 **禁止当主题默认**。 |
| 5090 最适合什么？ | 硬件原生最吃 **NVFP4**（Blackwell tensor core）。**文本编码器已经是 NVFP4-AWQ。** DiT 金线仍是 INT8；社区已有 `pruned_nvfp4` DiT，适合做成 **加速档**，不是替换金线。 |
| 精度会不会掉？ | **会，这是预期。** 量化是杠杆 2（每步 FLOP），和蒸馏/少步一样非无损。MAE 只记录、不改金线阈值；过目视+有声门才升为正式加速档。 |
| 最终形态 | **多量化并存**：金线 INT8 ConvRot；加速档 NVFP4 DiT（± turbo4 LoRA）；TE 保持 NVFP4；加载器按 safetensors 布局探测，不把格式焊死在 generate。 |

Comfy 社区公开对照（同一 pruned 骨干，**不是本仓 cafe 秒数**）：`pruned_int8_convrot` 21.0 GB / 2.17 s/it；`pruned_nvfp4` 12.5 GB / 1.90 s/it（约 **1.14×** 每步、显存 −40%）。对本仓金线 DiT 31.67s，若线性套用 ≈ **28s 量级**——远小于 turbo4 已拿到的 16.47s。所以 NVFP4 的价值是：① 与少步/多卡相乘的单步再砍；② 8 卡每卡一份权时显存更松。

## 1. 现状盘点（以本仓代码为准）

| 组件 | 今日默认格式 | 文件 / 入口 | 体积（公开/约定） | 备注 |
| --- | --- | --- | --- | --- |
| **DiT 金线** | AdaLN-pruned + **INT8 ConvRot** | `h3_dit_w4a8_open_int8`；权 `minimax_h3_fl2va_pruned_int8_convrot.safetensors` | ~21 GB | 主题默认。线性 INT8 GEMM，AdaLN/RoPE/gate 仍较高精度 |
| **DiT W4A8** | 权重 4-bit + 激活 INT8（Kijai 混合包） | 同 `h3_dit_w4a8*` 的 W4A8 打开路径 | 小于 INT8 | **禁止主题默认**（历史质量/契约） |
| **TE** | **NVFP4-AWQ** | `h3_nvfp4*`；权 `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors` | Comfy-Org 未改 | 已是 NVFP4。热路径仍 dequant→F32/BF16 GEMM，不是原生 FP4 矩阵乘 |
| **Video VAE** | FP16 官方 | `h3_vae_int8_cuda*` 解码路径 + 官方 fp16 包 | 官方包 | 金线禁止 TAE 成片 |
| **Audio VAE** | FP32 官方 | 同上族 | 官方包 | |
| **turbo4** | 金线 INT8 骨干 + LoRA residual | `h3_lora` 挂在 INT8 GEMM 之后 | LoRA 另文件 | 不改骨干量化 |

`pruned` 在这里**不是随机剪枝通道**，而是把可缓存的 AdaLN 分支从发布 BF16 里拿掉（H3 约 33B，其中 ~13B 是这类 AdaLN）。`int8_convrot` 再把 attn/mlp 线性打成 INT8，并在量化前做 **ConvRot（旋转）**：把权重分布转一下，压 outlier，INT8 才装得下而不炸。社区 `pruned_nvfp4` 是**同一套被 prune 的线性，改打成 NVFP4**。

`h3_dit_w4a8.c` 名字易误导：头文件写明量化线性走「ConvRot + INT8 act + resident INT8 GEMM」。W4A8 是早期/并列打开路径，不是今日 cafe 金线。

## 2. 名词（给半懂的读者）

**量化。** 把大浮点权压缩成更少的比特。少读显存、少算，画面会有误差。视频生成的「误差」没有后续层像 LLM 那样好抹平——8 步金线每步都是大更新。

**W4A8。** Weight 4-bit / Activation 8-bit。权更小（带宽友好），激活留 8-bit（精度友好）。矩阵乘通常仍走 INT8 tensor core，4-bit 权先解到 8-bit 或走混合核。本仓 Kijai 包是这条。

**INT8 ConvRot。** 权与激活都按 8-bit 乘（本仓金线 DiT）。ConvRot 是量化前的旋转预处理，不是「卷积加速」。

**NVFP4。** NVIDIA 在 Blackwell 上的 4-bit 浮点（E2M1 nibble + 分组 FP8 标度）。5090 的 tensor core **原生**吃它；Ada/Hopper 上是模拟，社区明确叫你回头用 `int8_convrot`。本仓 TE 布局（`h3_nvfp4.h`）：`U8[N, K/2]` 权 + `F8_E4M3` 分组 scale + 可选 AWQ `pre_quant_scale`。

**多量化。** 同一套 generate，按权重文件布局选 backend。用户选「质量档 / 速度档」，不是改源码换格式。

## 3. 5090 硬件账

RTX 5090 = Blackwell **sm_120**。相对 Ada 4090，多出来的就是 **FP4 / NVFP4** 吞吐；INT8 仍然很快，但不再是这张卡的「新」优势。

| 精度 | 5090 角色 | 本仓现状 |
| --- | --- | --- |
| FP16 / BF16 | 基准、AdaLN/VAE | 金线不用 BF16 DiT（太大、慢） |
| INT8 | 成熟、质量稳 | **DiT 金线** |
| FP8 | 中间档 | TE 的 scale 已用 E4M3；DiT 未立产品档 |
| **NVFP4** | 卡的峰值档 | **TE 已用**；DiT 仅社区权，本仓无 DiT 原生 FP4 GEMM |
| W4A8 | 带宽档 | 代码在，默认关 |

社区 Comfy 数字（Blackwell，**s/it 不是本仓 wall-clock**）：INT8 2.17 → NVFP4 1.90。混合/full NVFP4 几乎不更快（1.91–1.92）但更占显存——**该试的是 `pruned_nvfp4`，不是 24 GB mixed。**

工程缺口：本仓 TE 的 NVFP4 是 **解包再 GEMM**。DiT 要吃满 5090，需要 sm_120 的 NVFP4 GEMM（CUTLASS / cuBLASLt FP4），而不是把 12.5 GB 解成 FP32 再乘——那样只省加载，不省算。

## 5. 极致优化清单（按收益/成本/质量）

杠杆编号同 [principle-matrix](./2026-09-11-h3c-accel-principle-matrix.md)。量化只动杠杆 2。

| 优先级 | 动作 | 杠杆 | 预期（标注） | 质量 | 建议 |
| --- | --- | --- | --- | --- | --- |
| **P0** | TE prompt cache | 热路径消失 | 已测 TE ~14.9s 可归零 | 无损（同提示词） | 继续 Phase 2 |
| **P0** | Ulysses 接上（插点+pad+C3） | 4 | DiT 推断 2.5–4s（未测） | 置换；MAE 变大判 bug | 继续 Phase 2 |
| **P1** | turbo4 已测 | 1 | DiT 31.67→16.47 | MAE 41.97 记录 | 已落地；加快速动作验收 |
| **P1** | **DiT NVFP4 加速档** | 2 | Comfy ~1.14×/step；本仓待测 | **预期有损** | 新 preset，金线不动 |
| **P1** | TAE 成片（快档） | 5 | 推断 VAE 10s→1–3s | 明确非金线 | stub 已有 |
| **P2** | TE 原生 FP4 GEMM | 2 | 未能量化；今日 TE 墙钟主因是「每次都算」不是核 | 应接近无损 | 次于 cache |
| **P2** | NVFP4 ⊗ turbo4 | 1×2 | 相乘；4 步×更便宜单步 | 双损叠加 | 两档都过门再叠 |
| **否** | 未蒸馏 `--steps 4` | 1 | 红线崩 | 禁 | |
| **否** | 金线改默认 NVFP4 / W4A8 | 2 | 未过门 | 禁 | |
| **否** | Kijai W4A8 当主题 | 2 | 历史否决 | 禁默认 | |

叠加：NVFP4 砍的是**每步矩阵乘**；turbo4 砍的是**步数**；Ulysses 砍的是**单步墙**；TE cache 砍的是**另一段墙钟**。四者正交，数字相乘前各自过门。

## 6. 加速 SKU 测试方案（金线零污染）

**Preset 名（建议）：** `--preset nvfp4`（8-step、官方 VAE、cudnn 或显式 backend，只换 DiT 权）。  
叠少步另开 `--preset turbo4-nvfp4`（或 `nvfp4` + 已有 `--lora`），**禁止**第一次就把两刀焊死。help 写「非金线」。

**权：** `minimax_h3_fl2va_pruned_nvfp4.safetensors`（vonkaiser/lilcheaty Comfy 布局）。探测失败硬退出，不许静默回退 INT8。

**必测（GPU0，与现报同协议）：** cafe 冷 1 + warm×3；对照金线 78.74 / DiT 31.67 与 turbo4 63.69 / DiT 16.47。  
**质量：** 五帧 MAE **只记录**；目视（主体∩禁花屏∩有声）；**加快速动作用例**（上游 #14：4 步易拖影——NVFP4 8 步也要看动作）。  
**过门：** 尺子过 → 正式加速档；不过 → 文档记失败原因，默认不变。不许为让 NVFP4 好看而改金线阈值。

**接入成本（先探测再写核）：**

1. 打开 safetensors，对一层 `attn.qkv_proj` 确认是 NVFP4 布局（U8 nibble + E4M3 scale）而不是 INT8 ConvRot。
2. 最小路径：dequant→现有 INT8/F32 GEMM（证明能出片，**不是** 5090 最优）。
3. 产品路径：sm_120 NVFP4 GEMM。没有这一步，加速档宣传不得写「吃满 Blackwell」。

## 7. 多量化架构（目标态，现在不改代码）

```
generate
  └─ 探测 DiT 权（safetensors 头 / 约定后缀）
        ├─ INT8 ConvRot  →  open_int8     （金线）
        ├─ NVFP4         →  open_nvfp4    （加速档）
        ├─ W4A8          →  open_w4a8     （opt-in，禁默认）
        └─ 未知          →  硬失败
  └─ TE：已是 NVFP4，与 DiT 格式解耦
  └─ VAE：官方 / 未来 TAE，与 DiT 格式解耦
  └─ --preset 只选配方（步数、LoRA、sdpa），权路径可覆盖
```

原则：格式是**加载契约**，preset 是**采样契约**。两者相乘（`turbo4` + NVFP4 权）可以，但默认表分开写。金线命令继续钉死 INT8 文件。

## 8. 用户决策与下一步

已采纳：

1. 社区 NVFP4 **可以试**。
2. 精度损失未知、当作加速版本，**不替换金线**。
3. 最终支持多种量化。

**最小下一步（Phase 2 多卡/TE cache 空档或完成后）：**

1. 远端只读确认是否已有 `minimax_h3_fl2va_pruned_nvfp4.safetensors`；没有再拉（不进 git）。
2. 写探测：头布局 vs INT8 ConvRot，打印 tensor 名/dtype/shape。
3. GPU0 短测：能 encode 一层或 1-step 不崩，再 cafe warm×3。
4. 报告另册 `out/verify_nvfp4/`，禁止写进金线 REPORT。

Phase 2 当前仍优先：C2 DiT 插点、pad 截断、U=2/U=8、TE cache。NVFP4 与它们文件冲突面小（新 backend），但**不要**和 Ulysses 改 `block_device_compute` 抢同一周的远端机。
