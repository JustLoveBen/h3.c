> **机制深潜：** [2026-09-11-h3c-accel-survey-tech-deepdive.md](./2026-09-11-h3c-accel-survey-tech-deepdive.md)

> **金线矩阵：** [out/verify_accel_matrix/REPORT.md](../../../out/verify_accel_matrix/REPORT.md) §F

**问的是：** 详细分析 RH Lightning；若是 **8 卡 5090**，并优化本仓支持多卡，**目前方案**理论上生成 **5s · 1344×768 · 24fps** 大概多久？

**硬口径：**

1. **禁止**把 RH 的 4-step **28.7s** 说成「我们 8 卡也是 28s」。那是 8× RTX **6000D**、**同一套已 8 卡**上 50-step BF16 → 4-step 蒸馏为主的整栈，不是 8 卡相对 1 卡，更不是相对本仓 66s。
2. 「目前的方案」必须拆成 **A 保效果金线外推** 与 **B 对齐 RH 快档**。两套权、步数、注意力、cache 都不同。
3. 本仓 **当前无多卡实现**。下列 8 卡秒数全是外推，**本仓从未跑过 768p generate**。
4. 本仓金线尺子只在 **864×480 · 8-step INT8 · cudnn · 有声**。768p 必须先做 token/算力比，再套 Amdahl。

---

## 0. 一句话落点（先读这个）

| 场景 | 最可能 e2e（5s · 1344×768 · 有声 · warm） |
| --- | --- |
| **A. 金线外推**（INT8 8-step + cudnn，只加 Ulysses；**不**接 4-step/Sage/Cache） | **约 70–110 s**（中位粗看 **~85 s**） |
| **B. 对齐 RH 快档**（4-step LoRA + Sage2 + Cache-DiT + compile + TP2+U4） | **约 45–75 s**（**到不了 28.7 s**；5090 32GB 装不下 RH 的 60–66 GiB/卡 BF16 常驻） |

Amdahl 地板：即便 DiT 被 8 卡砍得很狠，**TE ~12–14 s + 768p VAE ~20–35 s 仍在**。金线 A 的 e2e 不可能接近 28 s。

## 1. RH Lightning 方案（半页，机制不是营销）

源码树：`third_party/accel_survey/MiniMax-H3-MultiGPU-Lightning/`（pinned SGLang `f8cbf000f4a5`）。启动：`scripts/start.sh` 硬编码「8× RTX 6000D：`--num-gpus 8 --tp-size 2 --ulysses-degree 4`」，`sage_attn` + `torch.compile` + Cache-DiT + turbo LoRA。请求默认 `num_inference_steps=4`，`target.short_edge=768`，`aspect_ratio=16:9` → **1344×768**；5s → H3 `17n+5` 桶 **124 帧** @24 fps。

三层相乘（README 自己写明 12.2× **含步数变化**）：

| 层 | 做什么 | 5s 768p t2va、**同一 8×6000D** |
| --- | --- | ---: |
| 后训练蒸馏 | 换学生权，请求 **4 步**（高动态建议回到 8） | 50-step **348.8 s** → 4-step **43.0 s（8.1×，占节省 95.5%）** |
| Sage2 + Cache-DiT + compile | 量化注意力 + 块级复用 + 编译图 | 43.0 → **28.7 s（再 ×1.50，占 4.5%）** |
| TP2+Ulysses4 | 权半切 + packed 序列 4 切；PCIe 无 NVLink | **此表无卡数变量**。另表：同 4-step 15s 竖屏 TP4+U2 **54.0 s** → TP2+U4 **48.2 s（~12%）** |

并行公式（SGLang `parallelism.mdx`）：`num_gpus = cfg × tp × ulysses × ring`。H3 金线 cfg 蒸馏 → **cfg=1 闲置**；PP/DP/Ring 未开。Ulysses：每层注意力两次 all-to-all（packed QKV 可打成一次）；TP：每 transformer 块 hidden-size all-reduce。无 NVLink 时 RH **故意少 TP、多 Ulysses**——文档把 TP 标成跨互连最差轴。

卡型钉死：NVIDIA **RTX 6000D**，`sm_120`，可用 **85,651 MiB**，PCIe Gen5 x16，**无 NVLink**，SM 2430 MHz，600 W。8 卡峰值 **60–66 GiB/卡** BF16 常驻；4 卡对照 INT8-ConvRot 36.8 GiB/卡。他们用 8 卡是因为 **768p 长序列注意力墙钟**，不是单卡 85GB 装不下。

质量：不宣称无损；RH 自训权 **未公开**；公开复现用 larryvrh turbo v4 EMA（4-step）或 LightX2V ref2v **8-step**。Cache-DiT 在已经 4-step 上 `max_warmup_steps=4`，跳步空间极窄。

**对本仓：** 抄 PCIe 上「少 TP、多 Ulysses」切 packed 序列。不抄 12.2×，不抄 4-step 进金线。本仓 INT8 已在单卡 32GB 常驻 480p，多卡故事是 **同轨迹砍 DiT 墙钟**，不是「显存换可跑」。

## 2. 分辨率：480p 金线 → 768p 的 token / 算力比

本仓公式（`h3_host.c` / `h3_cuda_generate.c`，**不是推断**）：

```
VAE 空间下采样 = 16（H3_VAE_SPATIAL_RATIO）
DiT patch = latent 上 2×2  → 像素等效 /32
latent_h,w = H/16, W/16
video_seq = latent_t × (latent_h/2) × (latent_w/2)
帧对齐 17n+5；latent_t = ((aligned-5)/17)×5+2
audio_t 口径：H3_AUDIO_LATENT_FPS=40；cafe 实测 packed 里 audio=414（立体声 2 tok/步）
```

| 量 | 864×480（已测 cafe） | 1344×768（目标） | 比 |
| --- | ---: | ---: | ---: |
| 像素 | 414,720 | 1,032,192 | **2.489×**（= HW 比） |
| 对齐帧（5s@24） | 124（mux 产品 120） | 124 | 1×（时长相同） |
| `latent_t` | 37 | 37 | 1× |
| 空间 token / latent 帧 | 15×27 = 405 | 24×42 = 1008 | 2.489× |
| `video_seq` | **14,985** | **37,296** | 2.489× |
| packed S（cafe：text 574 + audio 414 + video） | **15,973**（已测） | **≈38,284** | **≈2.40×** |

时间帧数不随分辨率变；空间 token ∝ H×W。768p vs 480p 的 **视频 token 就是像素比 2.49×**。

DiT 不算精确 FLOP（核融合、flash SDPA、带宽墙都会偏）：线性层 ∝ S（~2.40×），稠密 SDPA ∝ S²（~5.75×）。H3 形状 `HIDDEN=5376`、`INNER=7168`、`FFN=14336`、50 block。用「线性 GEMM + 2·S²·INNER 的 SDPA」粗分账，总 DiT 算力比大约 **3.8–4.4×**。下文取 **~4× 中位，3.5–5.0× 区间**，标为 **外推，非实测**。

VAE decode 近似 ∝ 像素×帧 → **~2.5×**（tile/deblock 可能再加点）。TE（Qwen 文本）与视频分辨率弱相关 → **按 480p 的 12–14 s 平移**。

## 3. 8×5090 vs 8×6000D

| 维 | RTX 5090 | RTX 6000D（RH 实测 / 公开拆） | 估时含义 |
| --- | --- | --- | --- |
| 架构 | Blackwell `sm_120` | 同代 `sm_120` | 核可移植 |
| 显存 | **32 GB** | **~86 GB**（smi 85,651 MiB） | **主差异** |
| 互连 | PCIe，无 NVLink | PCIe Gen5 x16，无 NVLink | 通信哲学可沿用「少 TP 多 Ulysses」 |
| CUDA 核 / 公开 FP32 | 21,760 · **104.8 TFLOPS**（NVIDIA Blackwell 白皮书） | 公开拆 **19,968** 核 · ~**97 TFLOPS**（非 NVIDIA 数据手册；**未钉**） | 单卡算力 5090 大约 **持平到略快（~1.0–1.15×）**，不是 6000D 的缩小版 |
| 带宽（公开） | 512-bit · ~1792 GB/s | 拆解常见 448-bit · ~1568 GB/s（**未钉**） | 同量级 |
| 功耗 | 575 W 级 | 600 W（RH smi） | 次要 |

**BF16 768p：** RH 8 卡 60–66 GiB/卡 → **5090 32GB 不能按 RH 配方常驻**。SGLang cookbook **2×5090 BF16** 必须 layerwise（~384 GiB 主机 RAM），50-step 768p **559.67 s**（denoise 525 + decode 33.6）；5-step 子测 inference **78.11 s**。那是 offload 尺子，与 Lightning 28.7 s 不是一个问题。

**INT8 480p：** 本仓单卡 5090 已常驻（金线）。DiT 50×4 linear INT8 约 **18 GiB**（`docs/nvidia_quant_contract.md` resident_all）。

**INT8 768p × 8 卡：** 激活随 S 涨（packed ~2.4×），但 Ulysses 按行切残差。每卡仍持 **一份 INT8 权副本**（TP=1）或半份（TP=2）。**推断：8 卡 Ulysses 下 INT8 768p 峰值大概率仍常驻 32GB**；**单卡 768p INT8 是否常驻未测**，激活+SDPA workspace 可能贴边/OOM。TP2+U4 比 U8 更省权、A2A 组更小。

## 4. 场景 A — 保效果金线外推（只加多卡）

锁死：INT8 ConvRot · 8-step · `sdpa=cudnn` · cfg=1 · 有声。多卡只加 **Ulysses**（建议 **TP=1 U=8**，或 RH 式 **TP2+U4**；56 头与 packed 对齐 64 均整除）。**不**接 4-step LoRA / Sage / Cache-DiT / compile。

### 4.1 单卡 480p 锚（已测）

`out/verify_accel_matrix/REPORT.md` §F，5090 cafe warm n=3：

| 段 | 秒 |
| --- | ---: |
| e2e | **66.06±5.80**（† 剔尖峰 **62.71**） |
| DiT | **31.37±0.05** |
| TE | 11.56±2.15（稳段 ~11.5） |
| VAE | 9.83±3.32（稳段 **~7.9**） |

其余（pack / audio / mux / host）约 8–13 s，未单独钉。

### 4.2 单卡 768p（未测，只作 8 卡分子）

| 段 | 算法 | 区间 |
| --- | --- | ---: |
| DiT | 31.4 × (3.5–5.0) | **110–157 s**（中位 ~125–135） |
| TE | 文本为主 | **12–14 s** |
| VAE | ×2.5 像素 + tile 税 | **20–35 s**（中位 ~22–28） |
| 其它 | 张量变大 | **8–15 s** |
| **单卡 e2e** | 相加 | **~150–220 s** |

Cookbook 2×5090 decode 33.6 s @768p 与「VAE 20–35 s」同量级，可作旁证，**不是**本仓 fp16 tile 路径。

### 4.3 Amdahl + k_eff（8 卡只砍 DiT）

```
e2e ≈ TE + DiT_1 / k_eff + VAE + 其它
```

Ulysses 注意力内部 A2A，**不是** 8 卡 100% 线性。2 卡效率若无实测，给 **0.6–0.85**（deepdive 已写）。8 卡 PCIe all-to-all 参与者更多，效率再降：取 **k_eff ≈ 2.5–5.0**（等效 8 卡效率 ~0.31–0.63），中位 **~3.5–4.2**。TP2 的 per-block all-reduce 在无 NVLink 上更差，故 **不要默认堆 TP**。

| 组合 | DiT_8 | +TE+VAE+其它 | e2e |
| --- | ---: | ---: | ---: |
| 乐观（DiT×3.5，k_eff=5.0，VAE 20） | 22 | 12+20+8 | **~62 s** |
| 中位（DiT×4.0，k_eff=3.8，VAE 25） | 33 | 12+25+10 | **~80 s** |
| 保守（DiT×5.0，k_eff=2.5，VAE 35） | 63 | 14+35+15 | **~127 s** |

**理论 e2e 区间：约 65–125 s。最可能 70–110 s。**  
理想线性上界（k_eff=8）大约 TE+VAE 地板 **~45–55 s** + DiT~15–20 s → **~60–75 s**——这是 **达不到的下沿**，不要当承诺。

质量：同轨迹并行，过门条件是相对单卡 5090 cudnn 的 PPM MAE ∩ 有声（768p 金线片子本仓还没有）。

## 5. 场景 B — 对齐 RH Lightning 快档

配方：4-step 学生 LoRA + SageAttention2 + Cache-DiT + `torch.compile` + TP2+Ulysses4。质量 **非金线**（蒸馏+量化 attn+cache+compile 都改计算；RH 无 MAE 表）。

RH 在 **已经 8×6000D 常驻 BF16** 上：4-step 43.0 s，三件套后 **28.7 s**。用 50/4 与 348.8→43.0 反推，步数不敏感项（TE/VAE/调度）大约 **~16 s**，优化后 DiT 大约 **~12 s**。5090 算力不弱于 6000D，**若显存同样常驻**，墙钟可以接近 25–32 s。

**5090 做不到「同样常驻」。** 60–66 GiB/卡 vs 32 GB。RH 自己的对照还显示 **TP4+U2 比 TP2+U4 更慢且更吃显存**，所以 **加 TP 救不了 32GB**。只能：

1. layerwise / 主机 offload（cookbook 2×5090 5-step 已是 **78 s** 量级；8 卡 offload **不会**线性降到 28 s）；或
2. 换成 INT8 骨干再挂 4-step LoRA（本仓 **无**产品 LoRA 加载器进默认；BF16 LoRA 打 INT8 要么反量化要么另蒸学生）。

本仓若走 C 管道 4-step + Ulysses，VAE 仍是 fp16 tile：**768p VAE 20–35 s 会单独超过 RH 整段 28.7 s 的很大一块**。SGLang 侧 VAE 更融、RH 地板才 ~16 s。

| 子情景 | e2e 区间 | 说明 |
| --- | ---: | --- |
| 幻想：8×5090 复刻 RH BF16 常驻 | 25–32 s | **显存不成立** |
| SGLang RH 栈 + 32GB offload | **50–90 s** | 通信+换层；以 cookbook 5-step 78 s 为悲观锚 |
| 本仓 INT8 + 公开 4-step LoRA + Sage + Ulysses（假设能接） | **50–75 s** | DiT 约减半再加 Sage，但仍付本仓 768p VAE |
| RH 数字直接当 8×5090 | **28.7 s** | **禁止** |

**理论 e2e 区间（可落地的 B）：约 45–90 s。最可能 45–75 s。质量：快档，非 MAE 金线。**

4-step 相对 8-step 的 NFE=1/2，但 TE/VAE 不动，所以 e2e **不是** A 的一半。

## 6. 总表

分辨率一律 **5s · 1344×768 · 24fps · 有声 · warmup 后 generation**（不含 load/compile/排队）。本仓 8 卡列为 **理论**。

| 场景 | 步数/精度 | 并行 | 理论 e2e 区间 | 置信度 | 质量 |
| --- | --- | --- | ---: | --- | --- |
| 本仓金线锚（已测） | 8 / INT8 + cudnn | **1×5090**，**864×480** | **~66 s**（DiT 31.3） | **高**（矩阵 n=3） | 金线 MAE∩有声 |
| A 单卡 768p | 8 / INT8 + cudnn | 1×5090 | 150–220 s | 低–中 | 同轨迹；显存可能贴边 |
| **A 8×5090 768p** | **8 / INT8 + cudnn** | **U8 或 TP2+U4** | **65–125 s**（最可能 **70–110**） | **低–中** | 保效果；768p MAE **未建** |
| A 理想 Amdahl 下沿 | 同上 | k_eff=8（达不到） | ~60–75 s | 仅作下沿 | — |
| RH 已测 | 50 / BF16 | 8×6000D TP2+U4 | 348.8 s | 高（RH 表） | 长 Euler，非本仓 GT |
| RH 已测 | 4 / BF16 蒸馏权 | 同上 | 43.0 s | 高 | 学生权 |
| RH 已测快档 | 4 / +Sage2+Cache+compile | 同上 | **28.7 s** | 高 | 非无损；**不是 5090** |
| **B 8×5090 768p** | **4 / LoRA+Sage+Cache+compile** | TP2+U4，**需 offload 或改 INT8** | **45–90 s**（最可能 **45–75**） | **低** | **非金线** |
| cookbook 旁证 | 50 / BF16 + offload | 2×5090 TP2 layerwise | 559.67 s | 高（公开） | 容量解 |
| cookbook 旁证 | 5 / BF16 + offload | 2×5090 | inference 78.11 s | 中 | 非 INT8、非 8 卡 |

**最可能落点：** 金线 768p 8×5090 大约 **70–110 秒**；快档大约 **45–75 秒**。都到不了 RH 的 28.7 s。
