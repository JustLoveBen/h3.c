**一句话：** 把 Sage / AdaLN / MagCache 划进「无用」是错的。业界相对 **FA2 / eager DiT / 50 步 BF16** 多数是真加速；本仓金线已经是 **8-step INT8 ConvRot + fused cuDNN SDPA**（cafe packed T≈15973, H=56, D=128，一层 ~47ms），赢 Flash 不等于赢这把 cuDNN。T2VA 有声 480P **~75s 仍是这条金线的地板**。官方 **4.44×** 是 50 步 BF16 768p **整栈**（2239.22→504.33s，TeaCache+compile+Sol），**不是 Sol 单核**。主线：**Tier-0** 质量默认 cudnn；**Tier-1 一等加速** = **`sol_cute`（4090/sm_89 主战场）** + **`sage3`（5090 主战场，见 [multi-gpu 架构文](./2026-08-25-h3c-multi-gpu-arch-speed.md)）**——不是「仅诊断」。条件图 host SDPA → cuDNN（KEEP）；**不要再测 nested-loop Sol。** 假 sage2 参考核禁止当产品后端。

禁止当质量默认：W4A8、关 deblock、`--frames 17` 冒充 5s、默认 magcache、TinyVAE 成片、未蒸馏 4 步、把本仓参考 Sage2 核当默认、SLA 当 8-step 插核。  
禁止把 Comfy 插件墙钟直接写成「本仓也能 2×」。  
禁止用「本仓已经证伪所以业界也没用」收束。

**判定四档（不许焊成一句「无用」）：**

| 档 | 含义 |
| --- | --- |
| **KEEP** | 本仓主线值得做（金线视觉无损 + native C，且预期 ≥5s 或条件图大头） |
| **OPT-IN** | 换基线 / 换配方 / 过视觉门才有意义；默认关 |
| **DROP-HERE** | 对本仓这条 8-step INT8+cuDNN 金线无收益；**业界不是骗局** |
| **DROP-FAKE** | 宣传对不上，或本仓实现根本不是业界那把核 |

## 1. 目标与无损定义（视觉）

**产品目标：** 单卡 4090，T2VA 480P 真 5s 有声成片。用户标准是 **成片视觉无损**，不要求推理 bit-exact / checksum 相同。

**金线配方（不可破，除非产品改口）：**

- `--seconds 5`（ffprobe 5.000s / 120 帧 @24fps），禁止 `--frames 17`
- cfg=1（H3 已 CFG 蒸馏）
- INT8 ConvRot DiT，fp16 VAE tile+deblock 0.28
- 默认有声 pack；默认 SDPA = cuDNN fused
- packed `[text|audio|video]`，cafe `seq≈15973`（T2VA）

**视觉门（操作定义，用 PPM 像素，不转码）：**

| 档 | 本仓实测对照 | 判定 |
| --- | --- | --- |
| 明显失败 | MagCache 0.08：帧 RGB MAE **52–68** | 主题/运动不可接受 |
| 仍失败 | 真 Sol 20 步：整帧 MAE **20–25**，吻部/地面漂 | 构图大形在，达不到无损 |
| 仍失败（更近） | Sol 前 10 步 dense：MAE **~5–6**，PSNR ~27–29 dB | 双主体还在，仍可见差异 |
| 通过 | 目视与金线同片不可辨；允许 checksum 不同 | 才允许 opt-in 进质量路径 |

没有「MAE < X 即过」的官方阈值。过门靠同 prompt/seed/ids 的 cafe 对照 + 人脸/口型抽帧。bit-exact 不是门。

**速度目标诚实分层：**

| 层 | 含义 | 是否承诺 |
| --- | --- | --- |
| 金线地板 | 8-step INT8+cuDNN 有声 480P **~75s** | 已实测，守住 |
| 间隙再抠 | 同一配方挤到 40–50s | **到不了**，不要再扫 |
| 换栈 4× | 官方 50 步 BF16 768p + TeaCache+compile+Sol | 那不是金线，也不是无损 8-step |
| 蒸馏 4 步 | Turbo LoRA / Super Acceleration | 质量代价，另开产品档 |

### 2.3 条件图路径（F2VA / L2VA）

`l2va_5s_knight_viscuda/generate.log`：

- `vision_encode_begin ... gemm=cublas`
- `vision_encode: done layers_ms=31505.0 gemm=cublas`，整段 vision **33191.3 ms**
- DiT 48.5s / TE 23.1s / VAE 14.1s / **total 142.2s**（`phase_ms total=142236.6`）
- 本跑 `cond_rows` 走 cache（`encode_ms=0.1`），VAE encode 墙钟未计入

| | cuDNN warm2 | 真 Sol warm2 |
| --- | ---: | ---: |
| te / dit / vae | 11.40 / **120.66** / 9.38 | 13.41 / **100.45** / 11.17 |

## 4. 官方与社区数字怎么读（纠正上一轮焊表）

### 4.1 官方 4.44× 是什么

来源（原文，不是转述；本节全部数字已于 08-25 二次审计时重新 WebFetch 核对，无出入）：

- [NVlabs/Sana `sol-engine` README](https://github.com/NVlabs/Sana/blob/sol-engine/README.md) 2026-08-17：MiniMax-H3 on RTX 4090 **4.44× e2e**；SM89 CuTe DSL
- [`models/minimax_h3/README.md`](https://github.com/NVlabs/Sana/blob/sol-engine/models/minimax_h3/README.md)：4090 **768p@5s，2239.22 → 504.33s = 4.44×**
- [`models/minimax_h3/RTX4090/README.md`](https://github.com/NVlabs/Sana/blob/sol-engine/models/minimax_h3/RTX4090/README.md) + [`rtx4090_fullopt.toml`](https://github.com/NVlabs/Sana/blob/sol-engine/config/minimax_h3/rtx4090_fullopt.toml)

| 官方 4090 fullopt | 本仓金线 |
| --- | --- |
| **50 步** BF16 FL2VA | **8 步** INT8 ConvRot T2VA |
| **1344×768** | **864×480** |
| 对照是 **未优化 Diffusers/SGLang BF16**（2239s） | 对照已是 INT8 + cuDNN fused |
| TeaCache thresh=0.10（测得 **14 次全算 + 35 次 reuse** / 49 decisions） | 8 步上 MagCache 已 FAIL |
| Sol-Attn τ=1，前 10 步 + 前 2 层 dense | 8 步若抄「前 10 dense」Sol 一次都不跑 |
| regional `torch.compile` + 层间 offload + 解码期常驻 BF16 VAE | 已融合 INT8 GEMM + cuDNN；compile 栈禁止 |
| 官方自己写：full-opt 用近似 cache + 稀疏；无感知质量门 | 本仓有 cafe MAE 门 |

**4.44× 是整栈相对 50 步 BF16 基线，不是 Sol 单核。**

官方 4090 **受控拆梯子**（相对「lossless opt」= 关 TeaCache 关 Sol，仍含 compile/融合）：

| 臂 | TeaCache | Sol-Attn | E2E | 增量 |
| --- | --- | --- | ---: | ---: |
| lossless opt | off | off | **1951.27s** | 1.00× |
| + Cache | on | off | **613.71s** | **3.18×** |
| + Cache + Sol | on | on | **504.33s** | **再 1.22×**（相对 cache 臂 −18%） |

相对未优化 2239s：融合/compile 只到 1951s（~1.15×）；**TeaCache 才是 4× 的主力**；Sol 在 cache 之后再砍一截。

### 4.2 上一轮焊错了什么

[accel-survey §1.8](./2026-08-21-h3-accel-survey.md) 用 **Spark 480p** 梯子：融合后 511.8s → 加 Sol 451.2s（**再砍 12%**），写成「官方 Sol 只承诺 12%」。

那是 **Spark、480p、已融合之后的一档**，不是：

- 官方 4090 承诺（4.44× 整栈）
- 也不是 4090 上 Sol 的增量（cache 后再 1.22×）
- 更不是「本仓换 Sol 只能 −12%」

Spark 5090 公开页（[H3-OnDevice](https://nvlabs.github.io/Sana/Sol-Engine/H3-OnDevice/)）：Spark 3.92×（832×480 50 步 710.6→511.8→451.2→181.3，**官方原话 cache 是最大单步**）；5090 4.52×（1344×768 1045.4→971.6→708.3→231.2）。两设备不是同一分辨率，不能横比秒数。  
注意梯子加法顺序不同：4090 受控表是 **cache 先、Sol 后**（Sol 增量 1.22×）；Spark/5090 页是 **Sol 先、cache 后**（Spark Sol 增量 511.8→451.2 = −11.8%）。§1.8 的「12%」就是后者，两个读法都对，只是臂不同——不许再混着焊。另：4090 用 TeaCache，Spark/5090 页写的是 First Block Cache。

## 5. 方案三列重判（业界原文 × 本仓金线）

上一轮把整表焊成 KEEP/OPT-IN/**DROP=无用**。DROP 必须拆开：**DROP-HERE** = 对本仓 8-step INT8 + fused cuDNN 金线无收益，业界对照别的尺子仍然成立；**DROP-FAKE** = 宣传对不上，或实现根本不是业界那把核。

金线尺子（不要跟论文尺子混）：4090、纯 C/CUDA、packed cafe **T≈15973, H=56, D=128**、一层 cuDNN **~47ms**、8-step INT8 ConvRot、T2VA 有声 480P **~75s**。业界赢 FA3 / FA2 / PyTorch SDPA / eager DiT / 50 步 BF16，**不等于**赢这把 cuDNN。

架构禁止 Python 侧车当产品质量路径。核要进 generate，须在 cafe 形状**稳定快于 0.92× 本仓 cuDNN 47ms（≈43ms）** 才谈速度；另过 §1 视觉门才谈默认。

### 5.0 主线仍在的刀（未改）

| 方案 | 业界是否真加速 | 和本仓金线 | 判定 |
| --- | --- | --- | --- |

### 本仓旧测「Sage2 满 seq ~9s/层 vs cuDNN ~150ms」——核对，但不要用来否定业界

**属实，但是测的不是 thu-ml Sage。**

- 文档：`docs/nvidia_optimization_plan.md` F1/G8，日期 **2026-08-16**：满 seq 1L **`H3_CUDA_SDPA_BACKEND=sage2` ~9.0s** vs **cuDNN ~150–177ms**；`check_sdpa` PASS（max_abs≈5e-4）。加 `__dp4a` 仍远慢。
- 代码：`h3_gpu_cuda.cu` L4509–4510 原文：*`SageAttention2-style opt-in — INT8 Q/K per-row + FP16 V. Not a full Sage2++ MMA port`*。核是 Br/Bc=64 的 shared-memory 循环：INT8 量化 Q/K、float softmax、FP16 V 累加（`h3_cuda_sdpa_sage2_kernel`），**没有** `mma.sync` / Tensor Core 路径。
- 现状金线：cafe 孤立 cuDNN 已是 **~47ms/层**（比 2026-08-16 的 150–177ms 更强）。同一把参考核相对现在的 47ms 只会更惨（约 9s/47ms ≈ 190×），不能解释成「业界 Sage 比 Flash 慢」。

结论：本仓 sage2 = **量化公式的参考实现**。业界 Sage2++ = **INT8 QK + FP8 PV 的 MMA kernel**。用参考核的 9s 去说「Sage 业界无用」是类别错误。

### 若要把真 Sage 接进本仓，需要什么

1. **Kernel ABI：** cafe packed `T≈15973, H=56, D=128`，可能还要 varlen/cu_seqlens（H3 packed `[text|audio|video]`）。thu-ml 快路径是 dense `sageattn()`；`sageattn_varlen` Triton 在 SGLang PR 里对 H3 长度 **更慢**（40.9s vs FA3 31.5s），他们改走 dense+跳 padding。
2. **精度：** 官方是 plug-and-play、端到端指标可忽略；本仓必须 `check_sdpa` + cafe 视觉门。INT8/FP8 注意力不是 bit-exact。Sage3 FP4 不适合 4090。
3. **速度门（硬）：** 在 cafe 形状 **warm 稳定 < 0.92 × 47ms ≈ 43ms**。赢不了这扇门就不要改默认。即使核赢，generate 里 SDPA 只占 DiT ~20%，e2e 上限远小于 Comfy「快一倍」。
4. **链接方式：** 静态链 thu-ml CUDA 核 / 自己写 sm_89 MMA，禁止把 Python sageattention 当产品路径。
5. **升级条件：** 满足 3+4 且过视觉门 → 从 DROP-HERE 升为 **OPT-IN**（仍默认 cuDNN）。现在没有这把核，**不排主线轮次**。

**一句话：** Sage 业界有用（vs FA2 / Comfy SDPA）。对本仓已经很快的 fused cuDNN，未移植的 MMA 核没有证据能稳定快于 47ms；本仓 9s 参考核只证明「假核很慢」，不证明「Sage 是骗局」。

## 6. 推荐路线（按 ROI，诚实）

按「金线视觉无损 + native C」排序。不是按营销倍数。主线**没有**因为这次重判而改变：T2VA 75s 地板还在。

### 不要做（浪费轮次）

1. **不要再抠 8 步 cuDNN 间隙（DROP-HERE）。** q1_spd 已证明 mmap/PPM 在噪声里。DiT 47.5s 是这条 dense 下限。
2. **不要再测 nested-loop Sol（DROP-FAKE）。** 351 vs 47ms 已死。不要推荐它。官方 CuTe 不是这把。
3. **不要对标 4.44×。** 要对标得换 50 步 BF16 768p + TeaCache 35/49 skip + compile。那不是 8-step INT8 金线。**4.44× 不是 Sol 单核。**
4. **不要把 SLA / Turbo-SLA / Super Acceleration / LightWan 80× 插进金线。** 它们业界是真的，但是另一套权/硬件/步数。
5. **不要把本仓参考 Sage2 核当默认。** 不要把 Comfy「Sage 快一倍」写成金线预期。真 MMA 未过 43ms 门之前不排轮次。
6. **不要默认 MagCache、W4A8、20 步更清、假 5s。** MagCache 业界不是假的；本仓 8 步实现过不了视觉门。

### 默认真源（守住 75s）

保持 q1 配方：8-step INT8 + cuDNN + 有声 + tile/deblock。真 Sol / TeaCache / FBC / Sage **全部默认关**。

**8 步金线写死：75s 是地板，别再抠。** 分解里没有任何 ≥5s 的无损刀：TE 11.6s（mmap 直传已做）、DiT 47.5s（cuDNN 稠密 Ada 上限，AdaLN/gate 融合上限 ~1.5s = DROP-HERE）、VAE 9.3s（tile 已调优）、开档等 ~7s。唯一可能再降的是刀 2 步缓存，那是**实验**，不是承诺。

**Sol 写死：现阶段不进任何默认**——8 步墙钟没降（71.5→77.6s）、20 步 DiT −16.8% 但视觉 MAE 20–25 不过。核赢不等于产品赢。不要再碰 nested-loop。

### 值得做的刀（KEEP 1 把 + OPT-IN 2 把）

**刀 1 — 条件图 host SDPA → cuDNN（KEEP，唯一主线；F2VA/L2VA）**  
T2VA 金线不吃这刀。L2VA viscuda 已证明 GEMM=cublas 后 **layers 仍 31.5s**，头号嫌疑是 `h3_vision_cuda.c` 的 host `sdpa()`（L480，OpenMP 三重循环）；本仓 DiT/TE 已有 cuDNN fused，接入路径现实。  
预期收益：条件图 total 142.2s 里最多砍 ~20–30s（**上限以 E3 孤立 profile 为准**，31.5s 里还有 cuBLAS GEMM 和搬运，不许把 31.5s 全记成 SDPA）。  
风险：低——与 TE GQA 同一类核，应接近 bit-exact；主题/锁帧门对拍即可。  
判停：孤立 profile 若显示 SDPA 占比 <5s，就停（说明瓶颈在别处，别硬换）。  
不做：为这刀改 DiT 注意力。

**刀 2 — 步缓存视觉门（OPT-IN 实验，必须 cafe A/B）**  
官方 4× 的真实主力是 cache，不是 Sol。本仓 MagCache 0.08 已 FAIL（skips=3 → 帧 MAE 52–68），所以 **不能假设 TeaCache/FBC 在 8 步无损**——这是待验假设，不是保证。缓存类技术业界是真的（§5 MagCache/TeaCache），失败的是 **8 步蒸馏配方上的本仓实现**。  
量化：8 步 step2–8 每步 ~5.31s。**跳 1 步省 ~5.3s（75.4→~70s），跳 2 步 ~10.6s**；蒸馏 8 步预期能安全跳的是 0–1 步（LightX2V #579：蒸馏后几乎不跳）。  
做法：opt-in TeaCache 或保守 FBC，阈值从严（不许抄官方 50 步的 0.10），**同一 cafe ids**，PPM MAE / 口型 / 音频波形三门。  
判停：任何一门不过 → 关掉、写 FAIL、不再调阈值二次捞；也**不要**为 cache 把金线改成 20/50 步再宣称加速（那是换产品）。

**刀 3 — 真 Sol 1000 hits 诊断（OPT-IN，非质量路径）**  
只回答「核是否还被 dense 门稀释」。当前 768/1000；关掉前 4 步/前 2 层 dense，算术上限 232×(45−13)ms ≈ **7s**，**视觉大概率更差**（vis20 已显示 hits 越多 MAE 越大）。只允许在独立目录跑；不过门就停。禁止 Triton 侧车产品化。**禁止 nested-loop。**

**AdaLN/gate 融合 = DROP-HERE，不是假技术。**  
Sol-Engine 称这是 H3 lossless 大刀，相对 **eager BF16** 成立。本仓 profile 实测（20 步）：AdaLN 1.5s + gate 2.3s = 3.8s，折 8 步金线**上限 ~1.5s，够不到 5s 门槛**；p5 反例乱融更慢。不列主线，不排轮次。若将来顺手做，必须 bit-exact 对拍 checksum。

### 若产品改口要「大约 4×」

必须同时承认三件事：

1. 基线换成 **50 步 BF16 768p**（或官方那条 Diffusers），不是 75s 金线。
2. 加速主力是 **TeaCache 类 skip**（官方 35/49），不是换 Sol 核，也不是 Sage。
3. 官方 4090 README **没有**感知质量门；本仓要用视觉门，过不了就不能写「near-lossless」。

蒸馏 4 步（Turbo / Super）是另一条产品，质量代价官方/作者都承认（运动拖影、塑料感、非无损）。本仓还缺 LoRA 加载器。相对的是 **20/30 步**，不是本仓 8 步。

### E1 — 真 Sol 1000 hits（诊断，非默认）

- 过门才允许讨论「是否进 opt-in CLI」；不过门 **关掉**，不要拧到 20 步假装 8 步赢了。

### E3 — Vision host SDPA → cuDNN（条件图，对应刀 1，优先做）

- 先孤立 profile：host `sdpa()` 在 27 层 layers 31.5s 里到底占几秒（计时打点即可，不用改核）。**若 <5s，停**，刀 1 作废。
- 再孤立对拍：1620×heads×dim host `sdpa` vs cuDNN，max abs / rel L2。
- 再 L2VA/F2VA 同图：`layers_ms` 应显著低于 31.5s；主题/锁帧门不回归。
- T2VA 金线不受益，不要拿 75s 当这刀的对照。

### 明确不做

- nested-loop Sol 再 bench（DROP-FAKE）
