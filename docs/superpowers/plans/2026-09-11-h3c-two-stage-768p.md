# 二采（低分草稿 → 高分精修）能不能让 768p 快很多？

> **现行评测尺子（2026-09-13）：** [2026-09-13-h3c-768p-eval-protocol.md](./2026-09-13-h3c-768p-eval-protocol.md) — 5s · **1344×768**。`--preset lift` 硬拒绝。本文估时仍有效，秒数仍是外推。  
> **后续优化方案见** [2026-09-11-h3c-next-opt-plan.md](./2026-09-11-h3c-next-opt-plan.md)  
> **极速 SKU 实现：** [2026-09-11-h3c-5090-turbo-implementation.md](./2026-09-11-h3c-5090-turbo-implementation.md)  
> **For agentic workers:** 估时/机制备忘，不是实现计划。禁止改 `h3_cuda_generate` 默认 / 单卡金线 KPI / 默认 `sdpa=cudnn` / 默认 8-step。不 commit。密码不入库。  
> **直出 768p 8 卡估时：** [2026-09-11-h3c-8x5090-768p-estimate.md](./2026-09-11-h3c-8x5090-768p-estimate.md)  
> **少步质量：** [2026-09-11-h3-few-step-quality.md](./2026-09-11-h3-few-step-quality.md)  
> **Sol Super Accel：** [2026-09-11-h3c-accel-survey-tech-deepdive.md](./2026-09-11-h3c-accel-survey-tech-deepdive.md) §2.2 · 摘录 `third_party/accel_survey/sol-engine-excerpts/`

**问的是：** 第一采低分辨率、第二采高分辨率，生成 **5s · 1344×768 · 24fps** 是不是会快很多？

**硬口径：**

1. 「二采」必须拆成 **同模型 H3→H3** 与 **异模型 H3→LTX（Sol Super Accel）**。机制不同，秒数不能混写。
2. 对照分母是 **单段 8-step 直接 768p**（金线轨迹外推），不是 50-step BF16，也不是本仓 480p 66s。
3. 本仓 **当前无多卡、从未跑过 768p generate**。下列 768p / 8 卡秒数全是外推。
4. 金线默认 **不改采样轨迹**。二采最多是独立快档 SKU，不能当无损开关。

---

## 0. 一句话落点

**可以作快档 SKU，不能当金线无损开关。**  
「会快很多」**只在**第二采是 **少步（约 2–4）或换更轻的 refiner（LTX）** 时成立。若两段都是 **8-step H3 768p 精修**，相对直出 768p **几乎不省，8 卡上还可能更慢**（多一次 VAE，Amdahl 地板被抬高）。

公开 **5s 768p 6.85s / 仓内中位 6.76s 是 2×GB200 Super Accel**，禁止写成 5090。本仓 **没有 LTX**。

---

## 1. 两种「二采」不是一件事

### 1.1 同模型 H3→H3（本仓接口能接线，但不是 Sol 那套算法）

意图：低分 **8-step T2VA** 出运动/口型草稿 → 像素或 latent upsample → 高分用条件图 **少步精修**。

| 段 | 典型形状 | 本仓能否接 |
| --- | --- | --- |
| 草稿 | T2VA **864×480**（金线已测）或 Sol 同款 **896×512** | 能。现网单卡 INT8 8-step 864×480 5090 cafe warm **~66s**（DiT ~31.4s） |
| 精修 | 1344×768，FL2VA / L2VA / Ref2VA /（非官方）init-latent | **条件图路径已有**；**没有**产品级「低分 latent ×2 upsample 再少步 denoise」 |

本仓可接的官方条件图（`tools/h3_cuda_generate.c`，cfg 默认 1）：

- `--first-frame` **F2VA** / `--last-frame` **L2VA** / 两者 **FL2VA**：jpeg → `h3_vae_encode_f32` → DiT COND 行 + Qwen vision。Vision cuDNN **KEEP**（条件图才吃到；T2VA 金线 0 收益）。
- `--ref-image` / `--ref-video` **Ref2VA**：必须 **另一份 Ref2VA DiT**（路径名含 `ref2va`；FL2VA 权拒绝静默回退）。`--ref-video` 会把整段参考编进 pack，**每步比 T2VA 更重**。
- `--init-latent` / `--init-first-frame` / `--lock-first-frame`：标注 **Debug / G3-lite**，**不是**官方 F2VA/L2VA，不能当产品二采。

**机制缺口（诚实）：** FL2VA/L2VA 锁的是 **首/末关键帧**，中间帧仍从噪声走完整高分 Euler——不是把草稿视频当 img2img 初值。Sol 的第二段是 **VAE encode + 学到的 ×2 latent upsample + 3 次更新**。把「upsample 后 FL2VA 8-step」叫二采，算法上更接近 **再生成一遍 768p（带端点条件）**，不是超分精修。

Ref2VA 更接近「看整段草稿」，但 RH 公开同机对照（15s 768p、已 8 卡）：t2va 4-step **48.2s** vs ref2va **73.0s**（~1.5×）；高动态 8-step 89.3 vs 134.3。精修若走 Ref2VA，**单步比直出 T2VA 更贵**。

### 1.2 异模型 H3→LTX（Sol Super Accel；本仓没有）

仓内 v2（`sol-engine-excerpts/super_acceleration/`，job 6304303）：

```
GPU A  Stage1 H3 FL2VA   896×512 / 124f / 4 DiT forwards
         LightX2V 4step_v0.1_544p LoRA  scale=0.0625
         cache 关 · TAEH3 出草稿像素 + H3 PCM
         ── TCP 直传张量（禁止中间 MP4）──
GPU B  Stage2 LTX-2.5    原版 LTX VAE encode + 学到的 x2 latent upsample → 1344×768
         3 updates（sigma 0.909375, 0.725, 0.421875, 0.0）
         layer0 dense，1–47 Sol-Attn cute_sm100 · TAEHV 成片
         扔掉 Stage2 音频，mux 回 Stage1 PCM
```

每请求 **2 GPU、零 TP/SP**。热 e2e 中位 **6.761s**（S1 4.292 + S2 service 2.447）。博客 **6.85s / 22.2×** 的分母是已发表 SGLang **152.3s @5s 768p GB200**，不是本仓 66s，也不是 8×5090。

本仓：**无 LTX-2.5、无 TAEH3/TAEHV、无 LightX2V LoRA 产品加载器、Stage2 核合同钉 `cute_sm100`。** Super Accel **不能落 5090**。

## 2. 速度账（相对「单段 8-step 直出 768p」）

空间 token 公式与估时文相同（`H3_VAE_SPATIAL_RATIO=16`，DiT patch 2×2，**不是推断**）：

| 量 | 864×480 | 896×512（Sol 草稿） | 1344×768 |
| --- | ---: | ---: | ---: |
| 空间 token / latent 帧 | 15×27 = 405 | 16×28 = 448 | 24×42 = 1008 |
| `video_seq`（5s，`latent_t=37`） | 14,985 | 16,576 | 37,296 |
| 相对 768p 空间 | **~1/2.49** | **~1/2.25** | 1 |

草稿 DiT **远小于**直出 768p：480p 相对 768p 视频 token ~1/2.5；线性 ∝ S，SDPA ∝ S²。估时文把 768p/480p 总 DiT 算力放在 **~4×（3.5–5.0）**。反过来：8-step 480p 草稿 DiT ≈ 直出 768p DiT 的 **~1/4–1/5**（单卡锚：31.4s vs 外推 110–157s）。

**但 e2e 不是两段 DiT 相加那么简单。**

### 2.1 精修仍是 8-step 768p H3 → 几乎不省

第二采若仍全 8 步、仍是 H3 768p packed 序列：

```
e2e ≈ TE×(1 或 2) + DiT_草稿 + VAE_低分解码 + [VAE_高分编码] + DiT_768p_8step + VAE_768p解码 + 其它
```

`DiT_768p_8step` **≈ 直出 768p 的整段 DiT**。草稿再便宜，也只是往上加一项。单卡上：直出外推 **150–220s**；8+8 同权大约 **200–280s**（TE 付两次更差）。**比直出更慢。**

FL2VA 还多 vision encode（KEEP 后仍不是 0）；Ref2VA 每步更重（见 §1.1 RH 1.5×）。

### 2.2 只有精修少步或换轻网络，才「优化很多」

少步必须 **匹配学生权 / LoRA**。本仓把金线 `--steps 8` 改成 4 **不换权会崩**（少步质量文红线）。精修 2–4 步同理。

Sol 快，是因为 Stage2 是 **另一套更轻的 LTX（3 update + Sol-Attn + TAE）**，不是 H3 再跑 8 步。H3→H3 没有这条刀，除非另训高分少步学生。

### 2.3 TE / VAE / Amdahl（8 卡上二采可能更差）

直出 768p 金线外推（8×5090，只加 Ulysses，**不**接 4-step/Sage/Cache）：e2e 最可能 **70–110s**，中位粗看 **~85s**。Ulysses **只砍 DiT**。TE ~12–14s + 768p VAE decode ~20–35s → 地板 **45–55s**（理想 k_eff=8 也到不了 28s）。

二采额外账单：

| 项 | 直出 768p | 二采 |
| --- | --- | --- |
| TE | 1×（12–14s） | **1× 或 2×**（两次 `h3_cuda_generate` 就付两次；同进程缓存文本才 1×） |
| VAE decode | 只 768p **20–35s** | 低分 **~8s**（480p 已测稳段 ~7.9）**+** 768p **20–35s** |
| VAE encode | 无 | 关键帧 jpeg：**小**；Sol/Ref2VA 整段高分 encode：**可能再 20–35s 量级**（未测，按像素比外推） |

8 卡上 DiT 被切薄之后，**多一次 VAE 会直接打在地板上**。8+8 同权：草稿 DiT_8 ~8s + 768p DiT_8 ~33s + TE 12 + VAE 8+25 → 粗算 **~90–110s+**，相对直出 70–110 **不赢，常更差**。  
8+2 且 **不**做整段高分 encode：才有机会落到直出带的下沿；一旦 Ref2VA 整段 encode，**e2e 可能回到直出中位甚至更慢**。

## 3. 粗区间（5s · 1344×768 · 有声 · warm；除 480p 锚外均为推断）

对照：直出 8-step INT8+cudnn —— **1×5090 150–220s**（未测）；**8×5090 65–125s，最可能 70–110s**。

### 3.1 1×5090（无多卡，现网能力）

| SKU | 配方 | 粗 e2e | vs 直出 768p 8-step | 质量 |
| --- | --- | ---: | --- | --- |
| 直出（对照） | 8-step T2VA 768p | **150–220s** | 1× | 同轨迹；显存可能贴边 |
| H3→H3 8+8 | 480p 8-step + 768p FL2VA 8-step | **200–280s** | **更慢** | 端点可锁；中间仍是完整 768p 轨迹；非超分 |
| H3→H3 8+4 | 精修 4-step **须匹配 LoRA** | **130–180s** | 大约 **0.7–0.95×**（省不多） | 快档；未蒸馏 4-step **崩** |
| H3→H3 8+2 | 精修 2-step **须匹配权** | **100–150s** | 大约 **0.55–0.8×** | 快档；本仓无此学生 |
| H3→LTX 4+3 | Sol 配方 | **不能跑** | — | 本仓无 LTX；6.85s **不是** 5090 |

1×5090 上「明显快一截」的上限大约是 **8+2 且 TE 只付一次、精修不做整段 encode**：直出中位 ~180s → **~110–140s**，约 **1.3–1.7×**，**不是数量级**。草稿已测 66s 里 TE+VAE 已占一半，高分 VAE 还要再付。

### 3.2 8×5090（本仓无实现；Ulysses 只砍 DiT）

| SKU | 粗 e2e | vs 直出 70–110s | 备注 |
| --- | ---: | --- | --- |
| 直出 8-step（对照） | **70–110s**（中位 ~85） | 1× | 地板 45–55s |
| H3→H3 8+8 | **85–130s** | **不赢 / 常更慢** | 768p 8-step DiT 几乎全付 + 多 VAE |
| H3→H3 8+4（匹配 LoRA） | **65–100s** | 重叠带；乐观 **~0.8–1.0×** | 精修 DiT 减半仍被 VAE 托住 |
| H3→H3 8+2（匹配权） | **55–90s** | 乐观 **~0.7–0.9×** | 仍难低于地板+草稿 VAE；整段 encode 则回到 **70–110+** |
| H3→LTX Super Accel | **禁止写 5090 秒数** | — | 6.76s 是 **2×GB200**；`cute_sm100` |

8 卡故事比单卡更残酷：直出已经把 768p DiT 砍到 ~20–60s 带，二采节省的就是这一段的步数差；**TE+VAE 不会变便宜**，二采还可能变贵。不要指望二采把 8 卡 70–110s 打到 RH 28.7s 或 Sol 6.85s。

## 4. 质量代价（必须写进快档说明）

1. **Sol 页面明确非无损**；仓内 `perceptual_quality_gate_run: false`，`speedup_claim: null`。成片观感来自 **LTX refine + TAEHV**，不是「H3 四步已经够好」。
2. **本仓 8-step 金线 vs 未蒸馏 4-step 会崩。** 二采精修少步同样要匹配权/LoRA；把精修 `--steps` 拧到 2–4 而不换学生 = 红线。
3. **FL2VA/L2VA ≠ 超分。** 只锁端点，中间运动/纹理与草稿不必一致；高分 8-step 金线权仍走自己的 768p 轨迹。
4. **有声：** Sol **扔掉 refine 音频，mux 回草稿 PCM**——口型合同在低分轨。草稿 480p/896×512 的嘴型映射到 768p 脸时有错位风险。H3→H3 若两段都出音频，还要决定跟哪一条；跟精修则草稿 PCM 白做，跟草稿则与 Sol 同一风险。
5. **VAE 往返：** 低分解码 → upsample → 高分编码（Sol/Ref2VA）引入 TAE/官方 VAE 域差与压缩。Sol 禁止中间 MP4，就是怕 H.264 再损；本仓若落盘再读会更差。
6. **尺子：** 快档对人眼可以「够用」。对本仓 PPM MAE ∩ 有声 vs **cudnn 8-step**：**预期不过门**（换分辨率 + 可能换步 + 可能换权 + 条件图）。768p 金线片子本仓还没有。

同类机制旁证（非 H3 秒数）：FastVideo LongCat 也是 16-step 蒸馏 480p → refinement LoRA 升 768p——质量来自第二段，墙钟两段相加。

## 5. 「会快很多」成立的条件（否则不要这么对外说）

同时满足才成立：

1. 精修 **NFE ≤ 4**（更好是 2–3），**并且**有匹配的高分学生/LoRA 或换轻量 refiner；**禁止**金线 8-step 权直接少步。
2. TE **只付一次**（同进程缓存 Qwen 文本；不要两次独立 generate）。
3. 避免整段 768p VAE encode；优先关键帧 COND。若必须 Ref2VA/`ref-video`，先承认每步 ~1.5× 税 + encode 税。
4. 接受 **快档、非 MAE 金线**；有声走草稿 PCM 时写清口型风险。
5. 8 卡还要把 VAE decode 单独做并行，否则 Amdahl 把二采优势吃掉。

不满足时的诚实句：**二采不会让 768p 快很多；8+8 还会更慢。**

## 6. 对本仓的产品结论

| 问题 | 答案 |
| --- | --- |
| 能不能做？ | **能做快档 SKU**（独立 CLI/preset，help 写非金线）。H3→H3 可接 F2VA/FL2VA/L2VA；Ref2VA 要另 DiT。H3→LTX **本仓做不了**。 |
| 能不能当金线开关？ | **不能。** 默认仍 8-step + cudnn；不改采样轨迹。 |
| 1×5090 会快很多吗？ | **8+8 否。** 8+2/4 且匹配权：大约从 150–220s 降到 **100–180s** 带（推断），最好约 **1.3–1.7×**，不是 2×+。 |
