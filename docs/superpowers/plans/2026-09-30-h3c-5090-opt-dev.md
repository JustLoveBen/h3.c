## 1. 里程碑划分（按依赖，不按愿望）

```text
M0 基线与可观测 ─► M1 清假账 S1–S3 ─► M2 KPI-A 热 e2e
                                   └─► M3 流水与显存 ─► M4 VAE 对齐 ─► M5 高分 attn / DiT 算子 ─► M6 KPI-B 收口
```

- M0 **不写核**：先能看见，再动手。M0 未出口，M1 起任何「变快」都无法证伪。
- M1 出口前禁止报任何 KPI 秒数（fine-opt §4 假阳性）。
- M2 与 M3 可并行开工，但 M2 的 A2 验收要等 M3 的 R11/R20 骨架至少能开关（否则 `total` 里的串行税说不清）。
- M4 是 KPI-B 第一刀（fine-opt §3.2 B1）；M5 是第二刀（B2）；M6 才允许声称「看见 ≤27」。

## 3. 代码结构约定（新代码必须遵守）

> 先看现状：`tools/h3_cuda_generate.c` **6553 行**、`h3_gpu_cuda.cu` **9707 行**、`h3_dit_w4a8.c` 6742、`h3_vae_int8_cuda.c` 3915、`h3_w4a8_cache.c` 1994、`h3_ffmpeg.c` 765、`h3_generate_preset.c` 176、`h3_selflift.c` 53、`h3_taomate.c` 384。

### 3.1 模块边界

### 3.2 新 kernel 放哪、怎么命名

- 文件：`h3_gpu_cuda_<module>.cu` + 同名 `.h`（现有先例：`h3_gpu_cuda_audio.cu/.h`）。VAE → `h3_gpu_cuda_vae.cu`；DiT epilogue 可留 `h3_gpu_cuda.cu` 但建议 `h3_gpu_cuda_dit.cu`。
- 导出符号：`h3_cuda_<module>_<op>[_<dtype>]_dev(h3_cuda *cuda, …, char *error, size_t error_size)`，返回 `int`（1 成功）；`_dev` 表示全设备指针（沿用 `h3_cuda_f32_to_f16_dev`）。例：`h3_cuda_vae_rms_convrot_f32_dev`、`h3_cuda_vae_qkv_split_rope_f16_dev`、`h3_cuda_vae_int8_window_attn_dev`。
- `__global__` 名：`h3_<module>_<op>_kernel`（沿用 `h3_f16_bhtd_to_f32_thd_kernel`）。
- 统一在 `h3_cuda_op_st(cuda)` stream 上 launch；不得自建全局 stream；不得在核函数封装里 `cudaDeviceSynchronize`。
- 每个新核必须有对照 probe（`tools/h3_<module>_<op>_probe.c`，与旧路径 maxabs）。
- CMake：加入 `h3_gpu_cuda` STATIC 库源列表（`CMakeLists.txt` 201 起），跟随 `CMAKE_CUDA_ARCHITECTURES`（89+120）。

### 3.3 env 开关命名与登记

- 命名：`H3_<MODULE>_<KNOB>`；MODULE ∈ `GEN`（generate 编排）、`VAE`、`DIT`、`W4A8`、`SDPA`、`CUDA`、`FFMPEG`、`AUDIO`、`AV`、`LIFT`、`TE`。
- 取值：布尔用 `0|1`；多态用小写枚举（`device|full`）。读取只经模块内 `env_is_one` / `env_flag_is_one`（现有两套，新代码统一用 `h3_env.h` **新增**薄封装 `h3_env_is_one` / `h3_env_str`，内部记录「已读取」供 `h3_run_report` 落盘）。
- **默认值文档化位置：§3.4 表**（唯一）。新增 env 不登记 = 卡未完成。
- 禁止运行时 `setenv` 改自己的配置（现 generate.c 6068–6071、2500–2501 是待清理的先例）。

### 3.5 日志字段命名
